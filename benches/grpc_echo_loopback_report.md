## 指標定義

- 固定負載基準以每秒 100 個請求發送，使用單一通道，最多允許 256 個未完成呼叫。Closed-loop C 會維持 C 個請求 coroutine，各自在前一個回應到達後才送出下一次呼叫。完成速率是完成的 RPC 數除以 completion window；該時間窗包含排空尚未完成工作的時間。
- E2E 定義為 t3-t0。t0-t1 是 client call 開始至 handler 進入；t1-t2 是 handler 執行時間；t2-t3 是 handler 離開至 client 收到回應。每次試驗的百分位數使用 nearest-rank quantile。表格 latency 以微秒列出 p50/p95/p99；每格是三次試驗各自百分位數的中位數。E2E 的 p99 不等於各階段 p99 的總和，因為各階段的百分位數可能來自不同 RPC。
- 客戶端核心等效值是 client process CPU time 增量除以 completion window。ProcessTime 在最後一個回應排空的計時端點取樣，早於 latency 樣本合併與排序。伺服器核心等效值是 server process CPU tick 增量除以父監控的 wall-clock 取樣時間窗；CSV 保留其偏移量與時間窗。
- Loopback 位元組與封包是測量取樣時間窗內 loopback 介面的 RX+TX counter 增量；表格列出每次試驗的 RX+TX 總和再取三次中位數。
- Send-Q/Recv-Q 欄位是每次試驗約每秒一次 `ss -tinH` 快照中取到的最大值，再取三次中位數。這是離散取樣的最大值，快照間隔中的尖峰可能未被觀察到。 以下另提供 client/server 分端的高併發 queue 中位數；分端最大值仍只涵蓋約每秒一次的快照。
- Heartbeat 欄位是 1 ms 客戶端計時器每次試驗 timer lateness 的 p95/p99/最大值，以及 missed ticks；表格取三次試驗各指標的中位數。client 在測量端點請求停止 heartbeat。
- CSV 另保存每程序 RSS、`/proc/PID/io` counter、父程序 CPU／各核心 softirq 增量、目標 block device busy counter、queue 樣本與 preflight 數值。96 次試驗中，client 與 server 的 `/proc/PID/io` `read_bytes`、`write_bytes` 計數增量均為 0。

## 範圍與限制

服務是兩個 Tokio 程序之間，透過明文 IPv4 loopback `127.0.0.1` 傳輸的 unary protobuf echo。測試不包含 ledger 工作、磁碟商務操作、TLS、外部 client、實體 NIC、RSS 或實體網路連線行為。計時模式包含每次呼叫的 clock 讀取、timestamp 欄位、payload 驗證、樣本收集、heartbeat 活動與 parent 監控，因此測量值包含基準工具本身的成本。t0-t1 與 t2-t3 包含 tonic／HTTP2 工作、主機本機佇列、排程與 loopback 傳輸，不是純網路傳輸時間。Handler 的 t1-t2 不代表伺服器程序的完整成本。CPU 數值描述個別基準程序，不代表整台主機的 CPU 使用率。
