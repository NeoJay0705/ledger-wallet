## LWT 持久化要求

ScyllaDB 2026.1 文件說明，LWT writes 在所有 commitlog sync modes 下都會同步寫入裝置，且 LWT 完成前會確認資料已到裝置。參考：[ScyllaDB 2026.1 LWT differences](https://docs.scylladb.com/manual/branch-2026.1/kb/lwt-differences.html)。因此，本測試不得描述為「沒有 fsync」、「每筆 LWT 一次獨立 fsync」或「停用 group commit」。

執行記錄必須保存 pinned release source 的 `force_sync` 執行路徑證據，包括來源版本、檔案路徑、相關行號或片段、source hash，以及 manifest。Runtime validation 必須確認實際載入 `commitlog_sync=periodic`、`commitlog_sync_period_in_ms=10000` 和 `O_DSYNC=false`。若來源證據缺漏，或 runtime profile 與要求不符，停止 workload，將 case 標為 invalid。

一般 periodic、非 LWT setup writes 可能在週期 flush 前回覆。這是設定的已知行為。本次 Wallet measured writes 是 LWT；不能把 setup write 行為外推到 LWT，也不能由本次結果推論其他非 LWT workload 的 durability latency。

## Wallet request 規則

每個帳戶使用記憶體 balance。既有 owner lock 保護同帳戶的連續操作。每筆已接受 request 僅執行一個同 partition `INSERT ... IF NOT EXISTS` LWT，measurement 中不執行 SELECT。每個 user 等待上一筆 reply 後才送下一筆。

只在取得 `Applied` acknowledgement 後更新記憶體 cache。Replay 回傳原始結果，不做額外 wallet mutation。遇到 unknown commit outcome 時 freeze 該帳戶並全域 fail closed。不可自動 retry。以上交易路徑與 [01-56 既有結果](01-56.development-analysis-scylladb-calibrated-s2-concurrency-benchmark.md) 相同。

## Strict preflight 與成功條件

每個 case 開始前，strict preflight 必須確認：

- 可用容量至少 `max(64 GiB, estimated requirement)`。
- CPU busy ≤10%。
- Device busy ≤5%。
- Available memory ≥32 GiB。
- AIO 與 runtime profile 有效。
- 有三個連續 passing samples。
- Pinned image、release binary、budget 和 frozen source evidence hash 符合設定。

完整成功 case 必須有 1,024,000 requests 全部 accepted、applied、replied；Credit 和 Debit 各 512,000。必須完整驗證 1,024 個 accounts 和 1,024,000 筆 ledger rows。Measured SELECT=0。Driver query delta 必須與接受的 requests 數相等。Errors、retries、request/connection timeouts 和 unknown outcomes 必須為 0。Pool target、worker bounds、required metrics、runtime configuration、source hash 與 cleanup 都必須通過。

失敗或任一必要 metric 缺漏時，將 case 標為 invalid。保存原始錯誤、partial verification、server/driver counters、source/runtime evidence 和 cleanup 結果。不得重跑此 case 以取代失敗結果。

## 比較基線與限制

比較基線為 [01-56 的 batch、S2/C512 case](01-56.development-analysis-scylladb-calibrated-s2-concurrency-benchmark.md)：RPS `15884.913190380918`；E2E p99 `171.704319 ms`；LWT p99 `50.036735 ms`。基線只供診斷比較；不重跑、不與新 case 合併直方圖，也不視為同次 campaign 的重複試驗。

這是單次短測，且 host OS 與裝置共用。校準寫入頻寬偏差曾達 107%；需在解讀中保留這項限制。單次結果不能建立統計顯著性、長期穩態、production SLA、物理裝置飽和，或獨立 fsync 延遲結論。

本次只建立 periodic profile pilot。不得稱作正式 27-case matrix，不得聲稱比較已證明哪種 commitlog mode 普遍較快或較安全。

```text
periodic case
  strict preflight -> offline/source/runtime gates -> fresh owned node
  -> verify periodic profile and pinned LWT force_sync evidence
  -> seed/preload -> run one C512 workload -> drain and full verification
  -> stop/inspect -> clean owned resources -> save result and evidence

Wallet request
  input -> submit -> owner lock -> worker/process_job
  -> ScyllaStore::commit LWT -> synchronous LWT persistence
  -> Applied -> publish memory cache -> reply
  -> after all replies: verify -> owned cleanup
```
