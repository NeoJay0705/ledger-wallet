# ScyllaDB Wallet 記憶體狀態 LWT：RF3/CL3 單 shard 並發與連線池掃描需求

日期：2026-10-12。
目標：RF3/CL3 單 shard、並發數與 data connection pool 掃描。
需求編號：01。文件序號：45。
狀態：授權四個單次 pilot cases；結果另記於 01-47。

本需求沿用 [01-31 ScyllaDB wallet benchmark](01-31.raw-requirement-scylladb-wallet-benchmark.md) 和 [01-42 memory-state LWT 需求](01-42.raw-requirement-scylladb-memory-lwt-benchmark.md)。本次只掃描單 shard 下的 worker 數與固定 pool 目標。交易模型、LWT 寫入、RF/CL、commitlog profile、deadline、監控與 owned cleanup 維持既有契約。

## 目標與範圍

使用 RF3、read/write CL `THREE` 與 `LOCAL_SERIAL`，執行四個不同並發與 pool 組合。每個 case 只執行一次。這是單 shard pilot sweep，不是 27-case formal matrix；成功 case 不代表 `formal_complete`，也不構成穩態或統計效能結論。本次不增加 integration 或 fault tests，不跑 RF1、S4、其他 pool 組合或額外 repeats。

三個 ScyllaDB nodes 使用既有 pinned image `scylladb/scylla@sha256:333b9ab3a3214c7f98af100711c51df7f58964e8227e6d26050e889ebb216df1` 與 `2026.1.14` release。沿用單一 service、共享 Session、`wallet-memory-lwt-v1`、一個 conditional INSERT LWT、measurement window 零 SELECT、既有 commitlog batch fsync acknowledgement、driver/server deadline 與 required metrics。

本文件要求收集資料以核對工作負載、pool 與正確性。它不預設 worker 數增加會提升效能，也不把連線池的變化解讀為獨立因果效果。

## Workload

每個 case 固定使用 1,024 個 accounts，每個 account 執行 1,000 個 requests，共 1,024,000 筆。每筆 request 等待 reply 後，同一個 client 才送下一筆。每個帳戶的 owner lock 保持交易循序；worker dispatch 使用 round-robin shared worker pool。

| 項目 | 固定值 |
|---|---:|
| Accounts | 1,024 |
| Requests per account | 1,000 |
| Total requests per case | 1,024,000 |
| Initial balance | 100 per account |
| Operations | amount 1 的 Credit、Debit 交替 |
| Expected successful outcomes | 1,024,000 `Applied` |
| Expected final balance | 100 per account |
| Expected final version / logical clock | 1,000 / 1,000 per account |
| Expected ledger rows | 1,000 per account、1,024,000 total |

驗證上限為每帳戶 1,000 rows；本 workload 正好到達此上限。每個 account 必須完整驗證，不能以總列數取代逐帳戶核對。

## Worker 與 data connection pool cases

`S` 是每 node 的 shard 數；本 sweep 固定 `S=1`。`C` 是 worker 數與應用層 CQL in-flight 上限。`P` 是每 node、每 shard 的 data connections 目標。三個 node 的 pool 目標為 `D=3×S×P`。此 sweep 按既定估算 `P=ceil(C/50)` 設定；這是本次 case matrix 的 pool 配置規則，不是一般 worker-to-socket 假設。

| Case | S | C | P per node per shard | D across 3 nodes |
|---|---:|---:|---:|---:|
| 1 | 1 | 128 | 3 | 9 |
| 2 | 1 | 256 | 6 | 18 |
| 3 | 1 | 512 | 11 | 33 |
| 4 | 1 | 1,024 | 21 | 63 |

每個 case 使用 round-robin shared worker pool。帳戶 owner 仍在 read-from-cache、compute、conditional commit 和 reply 全程維持同帳戶序列化。`C` 和 `D` 分開記錄；pool readiness、實際連線 target 與測量期間 connection samples 必須通過 runner audit。

## ScyllaDB 與 host profile

| 設定 | 值 |
|---|---|
| Node count | 3 個隔離 nodes，共用同一 host 與 SSD |
| ScyllaDB | pinned `2026.1.14` image |
| Shards | 每 node `S=1` |
| Replication | RF=3、`durable_writes=true` |
| Wallet read / write CL | `THREE` / `THREE` |
| LWT serial CL | `LOCAL_SERIAL` |
| Commitlog | `commitlog_sync=batch`、`commitlog_use_o_dsync=false` |
| Write acknowledgement | commitlog batch fsync 後 |
| Batch window assumption | 不假設固定 batch timer 或每筆交易獨立 fsync |
| Routing | round-robin，account owner lock 保持每帳戶序列 |

沿用 CPU affinity：node A 使用 CPU `0`，node B 使用 CPU `2`，node C 使用 CPU `4`；service、load 與 monitors 使用 CPU `6,7,14,15`。本機使用既有 SMT 與隔離配置。

Wallet measurement path 維持 `wallet-memory-lwt-v1`。交易以一個 conditional `INSERT ... IF NOT EXISTS` 同時處理 static state 和 ledger row。交易成功 acknowledgement 後才更新 cache。Measurement window 內必須是每個 accepted request 一個 LWT CQL request、零 SELECT。Seed、preload 與 full verification 在 window 外。

Paxos 或 commitlog group commit 可能造成額外內部工作。CQL request、LWT、commitlog flush counters 不可解讀為每筆交易各自觸發一次 fsync；flush count、bytes、cycle、allocation 與 pending 只作 node/shard 層觀測。

## Strict gate、停止條件與證據

Pilot mode 本身不執行既有 27-case formal gate。Target-only supervisor 必須在每個 case 啟動前，對相同 host 與 output filesystem 呼叫既有 `strict_formal_preflight`。四個 case 逐一 gate；任一 case preflight 不通過時，不建立該 case cluster，也不啟動後續 case。

Case 成功條件：

- strict preflight 與所有 required metrics 通過。
- Runtime schema、RF3、read/write `THREE`、`LOCAL_SERIAL` 和 profile metadata 相符。
- pool readiness 和 socket audit 符合該 case 的 `D`，且沒有非目標連線。
- 1,024,000 個 requests 全部 accepted、applied 並收到 reply。
- driver query delta 為 1,024,000；measurement SELECT 為 0。
- errors、retries、driver request timeouts、connection timeouts 和 unknown outcomes 均為 0。
- 1,024 個 accounts 全部通過 cache/state/ledger 驗證，每個有 1,000 rows。
- owned containers、network 和 data cleanup 全部 clean。

若 case failed、`passed_relaxed`、metrics invalid、strict preflight failed 或 cleanup 不 clean，立即停止後續 cases。保留 partial artifacts 與未知 outcome；不自動重試、不調整 timeout、不改 CL、不變更 workload 或 pool 規則來重跑。

## 必須保存的結果

每 case 記錄 run/trial ID、source/binary hashes、命令列、strict preflight samples、keyspace/CL/schema、pool target 和 connection audit、accepted/applied/reply/error counts、driver counters、CQL in-flight 與 busy/idle worker peaks、measurement RPS、E2E p50/p95/p99、CPU、I/O、以及每 node/shard 的 commitlog flush、bytes、cycle、allocation 與 pending 指標。

四 case 各只有一次執行。`C` 和 `P` 隨 matrix 同時變化，因此結果只能比較本次配置組合，不能單獨歸因於 worker count 或 pool size。短 pilot 亦不得宣稱穩態效能或統計顯著差異。
