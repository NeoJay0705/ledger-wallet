## Workload 與正確性結果

固定 workload 為 50,000 users × 200 requests，共 10,000,000 筆預期交易。每帳戶以 amount 1 的 Credit、Debit 交替，各 100 筆；初始 balance 為 100。單一 service 共用一個 Session。ScyllaDB 使用 pinned 2026.1.14 image `scylladb/scylla@sha256:333b9ab3a3214c7f98af100711c51df7f58964e8227e6d26050e889ebb216df1`、RF3、wallet CL=THREE 與 `commitlog_sync=batch` fsync-before-ack。三個隔離 node 共用同一 host 和 SSD，SMT enabled。CPU affinity 沿用 S4 配置：node A CPUs 0,1,8,9；B CPUs 2,3,10,11；C CPUs 4,5,12,13；service/load/monitor CPUs 6,7,14,15。S4、P4 的目標為 D=48 data connections、每 node 16 條。每個 user 對應固定 per-user worker；每 worker queue capacity 為 1；global admission capacity 為 50,000。Seed 與 verify 的 setup concurrency 為 48。

失敗時停止新工作，並讓已接受工作 settle。未知提交結果不會被當成確定失敗重送。每個 unknown result 都可能已提交，也可能尚未提交；不能只根據 client error 推斷其最終資料狀態。

Driver query delta 為 5,660,610，恰為 1,886,870 個 attempted requests 的 3 倍；driver errors 為 49,915。Driver retries、request timeouts 和 connection timeouts 均為 0。Server 回報 CL=THREE write timeout：`received: 2, required: 3, write_type: Simple`，錯誤訊息為 `Operation timed out`。這是 Scylla write consistency timeout；driver request timeout counter 為 0，兩者不能混為一談。

完整 workload 正確性驗證未通過：`accounts_verified=0/50,000`、`failures=50,000`、`complete=false`。`accounts_verified` 計算符合每帳戶完整 200 筆預期的帳戶數；0 表示沒有帳戶通過，不表示未執行逐帳戶檢查。Verifier 的 `ledger_rows_seen=1,830,256` 只累計成功返回的 `verify_account` rows。它不是全資料庫 ledger count，也不能單獨證明資料遺失。

## 結論與後續範圍

Per-user owner routing 達到同帳戶順序處理，觀察到的 account 與 worker queue wait 很短。但本 case 同時把 DB workers／交易 in-flight 上限設為 50,000。固定 48 條 connections 並不代表系統能承受 50,000 個並發交易。這個 workload 在既有本機 profile 與 timeout 下未能完成。

後續評估可保留 user-to-worker 1:1 routing，並獨立限制 DB in-flight。先以 48 個 in-flight 做單 case 對照，再評估逐步增加上限。這個方向尚未實作或執行；本報告不調高 timeout、不改 CL，也不宣稱已驗證該方向。

本機三個 Scylla nodes 共用同一 host 與 SSD。S4 使用每 node 兩個 physical cores 的四個 SMT threads。這些結果不代表三個獨立故障域、production tuning 或其他儲存裝置的表現。

```text
input
  -> run_clients
  -> run_client (one user; await each reply)
  -> Service::submit (account owner lock)
  -> dedicated worker[account_id]
  -> worker_loop -> process_job -> ScyllaStore::load
  -> SELECT static state
  -> SELECT ledger key
  -> compute
  -> ScyllaStore::commit
  -> single-partition UNLOGGED BATCH via shared Session (48 data connections)
  -> CL=THREE / commitlog batch fsync acknowledgement
  -> reply
  -> next request

write outcome unknown
  -> freeze account / fail fast
  -> stop new admission and settle accepted jobs
  -> verify accounts and ledger
  -> remove owned containers, network and data
  -> report failed custom case
```
