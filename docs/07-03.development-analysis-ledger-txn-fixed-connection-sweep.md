## 2. Workload

- 2,000,000 requests: 50,000 accounts × 40; 256 queues. TiDB uses 256 regions per table, no replication factor; one queue maps to a region.
- Fixed connections per series (16 except CPU8+ 32-connection curve); ascending batch grid: 50, 100, 250, 500, 1,000, 2,000, 4,000, 8,000.
- Stop after two consecutive points each below 105% of the best earlier RPS; a non-sampler failure ends the curve. 8,000 is the cap. Saturation is the smallest successful primary batch at or above 95% of curve maximum; failure-limit/cap curves are labeled observed-range.
- Replicates are the saturation point and its next-lower grid point (only saturation point if batch 50); replicates do not affect curve selection. Idle gate precedes each attempt. Flush-await >2 ms triggers one rerun; successful rerun replaces the primary. Imported connsweep points are marked imported.

## 10. Limitations and file index

- Single-run points and selected replicates do not characterize variance comprehensively; observed-range labels do not imply a measured saturation point.
- CPU8+ shared placement may perturb sampler measurements; SMT siblings are shared. TiKV per-thread CPU and run-end region distribution were not measured.
- PostgreSQL network is computed from timestamped wrapper `net.csv` samples inside the summary measurement window; `n/a / n/a` means the network file is absent or has no usable in-window sample pairs.
- File index: `artifacts/fixconn-*.csv`; each row’s attempt directory contains `summary.json`, resource summaries, optional `durability.json` and `client/topology.json`, failure evidence, cleanup, and idle-gate evidence. Imported rows refer to original connsweep attempt paths.
- Empty or partial campaigns are reported with `n/a` and “no data”; absent artifacts are not inferred.
