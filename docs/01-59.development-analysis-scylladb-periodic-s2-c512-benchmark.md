需求編號：01。文件序號：59。

狀態：首次啟動在 periodic runtime configuration gate 停止。未啟動 Wallet CLI，沒有 measured workload。修正流程見 [01-60 setup correction](01-60.development-design-scylladb-periodic-config-probe-correction.md)。後續成功 case 的結果另記於 01-61。

本次 periodic profile 規格見 [01-57](01-57.raw-requirement-scylladb-periodic-s2-c512-benchmark.md) 與 [01-58](01-58.development-design-scylladb-periodic-s2-c512-benchmark.md)。本文件只分析第一次實際產生的 setup evidence，不填性能結果。

## 首次啟動

Job 為 `calibrated-single-node-rf1-s2-periodic-c512-20261013T012925Z`；唯一 run 為 `run-20261013T015038Z-0010535e`。設定為 N=1、RF=1、S=2、C=512、P=3、D=6、1,024 users × 1,000 requests。Runner exit code 為 1，case 標記為 failed。

External strict preflight 通過，並取得三個連續 passing samples。Scylla image、I/O profile、pinned-release source evidence 與 source hash validation 通過。REST runtime probe 回報 `commitlog_sync=periodic`、`commitlog_sync_period_in_ms=10000` 和 `commitlog_use_o_dsync=false`。

Gate 另外要求從 `system.config` 驗證 `commitlog_sync`。Probe 使用 `cqlsh SELECT JSON`。Pretty output 對字串值加了一層反斜線跳脫。現有 JSON parser 沒有解出 `periodic`，並把 parser result 存為 null。

這個 null 是解析結果，不是 Scylla database 返回 NULL。因為 `system.config` gate 沒有成功，runner 按 fail-closed 規則停止。REST probe 的成功不能取代這項 gate。

| 項目 | 首次 run 結果 |
|---|---|
| Strict external preflight | 通過；3 個連續 passing samples |
| REST periodic / period / O_DSYNC | `periodic` / `10000 ms` / `false` |
| Pinned-release LWT `force_sync` source evidence | 有效 |
| `system.config` enum validation | 失敗；escaped pretty JSON 未被既有 parser 解碼 |
| Wallet CLI / accepted requests | 未啟動 / 0 |
| Measurement window | 未建立 |
| RPS、latency、stage metrics、ledger verification | 未測量；應記為 N/A，不得填 0 |
| I/O observer | 25 samples 後正常停止；沒有可分析的 workload window |
| Cleanup / terminal resource audit | node、data、network 已清理；terminal audit valid，無 owned container/network ID |

## 結果分類

這是 setup/config probe failure，不是 Wallet request failure，也不是 periodic write performance 結果。沒有資料可比較 RPS、E2E latency、LWT latency、throughput 或 verify counts。

Strict preflight 和 source evidence 的成功只證明 workload 前的對應 gates 通過。由於 periodic runtime profile 的 `system.config` enum 未驗證，不能宣稱完整 runtime gate 通過。也不能從 parser 的 null 值推論 Scylla 設定本身為 null。

第一次 run 保持 failed 狀態及原始 provenance。不得覆寫為成功，不得把它加入性能統計，不得把 25 個 observer setup samples 當成 measurement samples。這次失敗不會改變原始負載，也不授權 app retry。

First run artifacts 保存當時的 source hashes 與 end-hash match 狀態，但前一版本的完整 source bytes 不可用。因此本分析不宣稱有完整的前後 source diff；hash 紀錄只用於識別已保存的 provenance。

## 修正與後續分界

[01-60](01-60.development-design-scylladb-periodic-config-probe-correction.md) 記錄 probe 修正：保留 REST 和原始 JSON 證據，另以 plain CQL 查詢 `system.config` 的 `commitlog_sync`；驗證 exit code、欄位、單列、精確名稱及 enum。不得做任意 JSON unescape，也不得放寬 fail-closed gate。

只有離線 replay、negative fixtures、完整 runner suite、compile、exact dry-run 和 source evidence replay 通過，且新 inputs 經 root review/freeze 後，才能用 fresh owned job 執行一次相同 workload。不得重用第一次的 keyspace、data、container 或 network。新結果需以獨立 job path 寫入 01-61；第一次 setup failure 永遠保留為失敗記錄。

```text
strict preflight -> create node -> REST config probe passes
  -> system.config JSON rendering escapes enum
  -> parser cannot validate -> strict gate stops
  -> no Wallet CLI or measurement -> preserve setup evidence
  -> stop and clean confirmed owned resources

correction -> offline tests and source replay -> freeze new inputs
  -> fresh strict preflight and node -> REST + plain CQL gates
  -> one measured case -> full verification -> cleanup -> report 01-61
```

本次使用的固定 workload/profile 詳見 [01-57](01-57.raw-requirement-scylladb-periodic-s2-c512-benchmark.md)。LWT 在 pinned Scylla release 的所有 commitlog sync modes 下仍同步持久化；periodic 不代表沒有 fsync，也不保證禁止 group commit。
