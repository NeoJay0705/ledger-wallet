# ledger-tikv6 — Design
1. scripts/txn_tidb_run.py: new flag `--tikv-cpus {4,6}` (default: unchanged 8-CPU/4-per-store layout); `6` valid only with `--cpus 8 --tidb-extended`, selects profile {'tikv':['0-2','4-6'],'tidb':'3,7,10-15','client':'8-9','sampler':'8-9'} and per-store quota 3; per-store quota used consistently in `docker run --cpus`, docker_resource_assignment check (quota, nano cpus), sampler allocated cpus, `tikv_cpu_pct_of_quota` (currently `4*count`) and placement JSON (`tikv_cpus_total`, `tikv_quota_per_store`). Default behaviour/tests unchanged. `select_profile` stays the tested pure helper.
2. scripts/fixconn_sweep.py: new series `tidb-c6x-n16` (db tidb, wrapper `--cpus 8 --tidb-extended --tikv-cpus 6`, conns 16, files/dirs named `...-c6x-n16-...`). Per-series grid [2000,4000,8000], no imports, no stop rule: completion `grid-complete` when all three have an effective OK primary, or `failure-limit` on a non-sampler failure (stop). Extra-run rule: flush rerun as now; plus one `replicate` row for a batch whose RPS differs from artifacts/fixconn-tidb-c8x-n16 (not published) effective primary of the same batch by more than 15 % (|ratio-1|>0.15). `run --series all` and its audit keep the original five series only; c6x is selected explicitly. audit for c6x: completion, three batches OK, expected windows, shared-CPU evidence, extra-run rule satisfied, idle evidence, nothing launched after termination. Existing 5-series behaviour and all existing tests unchanged.
3. scripts/tikv6_report.py + tests -> docs/08-03.development-analysis-ledger-txn-tikv6-tidb8.md (self-contained, reads artifacts; uses fixconn_sweep/fixconn_report helpers read-only where they fit).
