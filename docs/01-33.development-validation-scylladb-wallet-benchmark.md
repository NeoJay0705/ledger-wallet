## 實際路徑與結論邊界

```text
Credit / Debit
  -> Service::submit
  -> bounded admission
  -> account owner
  -> worker_loop / process_job
  -> load (2 SELECTs)
  -> compute
  -> commit (1 same-partition, 2-statement UNLOGGED BATCH)
  -> RF=3 replicas, CL=THREE commitlog fsync acknowledgement
  -> reply
  -> verify
  -> stop, inspect, cleanup owned resources
```

Runner 流程：

```text
Python main -> preflight -> run_trial -> verify
  -> stop_and_cleanup owned resources -> write run reports
```

受測 release 使用 `commitlog_sync=batch`，沒有另外驗證 per-write fsync profile。沒有測試 periodic 替代設定。Commitlog flush counters 不是 syscall 數或 request 數。Host policy 不允許 `strace`。Process-crash test 不模擬 power loss。三個 nodes 共用一個 host 與 device，不是三個獨立 failure domains。保留的 inspection 記錄可能顯示非零 container exit，即使 cleanup 狀態為 clean。每 case 一次短 pilot 不能證明 steady-state 行為或資料庫引擎勝負。

`target/scylla-wallet` 下的原始 run artifacts 保存在外部 evidence archive；本文引用的 Git 小檔、derived summary 與 raw archive 對照見 [Scylla evidence package](../benches/data/scylla_wallet/README.md)。本文記錄精簡數值。
