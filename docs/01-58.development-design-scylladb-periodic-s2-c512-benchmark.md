## LWT 同步持久化規則

[ScyllaDB 2026.1 LWT differences](https://docs.scylladb.com/manual/branch-2026.1/kb/lwt-differences.html) 說明，LWT write 在所有 `commitlog_sync` modes 都會同步寫入裝置，並在 LWT 完成前確認資料已到裝置。因此，periodic 設定不代表 Wallet LWT 不做同步持久化。

每次 live case 必須保存與 image release 完全相符的 source evidence。證據需記錄 source version、source hash、文件路徑、`force_sync` 呼叫或分支相關行號/片段，以及 evidence manifest。Evidence 要能連結 LWT 到強制同步路徑。

Runner 同時驗證容器實際載入的 `commitlog_sync=periodic`、period `10000 ms` 和 `O_DSYNC=false`。Image digest、source evidence 或 runtime profile 任一不符時，不啟動 workload，並將結果標為 invalid。

一般 periodic 非 LWT setup writes 可能在週期 flush 前回覆。這不改變上述 LWT 規則。報告要分開說明 setup 與 measured LWT，不可把 setup writes 的 acknowledgement 推廣到 LWT，也不可將結果外推到其他非 LWT workload。

不宣稱關閉 fsync、不宣稱一筆 LWT 對應一次獨立 fsync，也不宣稱 group commit 被禁止。LWT force-sync 路徑可能與普通 periodic writes 有不同 persistence timing；結果只描述實際 pinned release 與設定。

## Wallet service 行為

每個 account 的 balance 與 version 保留在記憶體 cache。Owner lock 維持同帳戶操作序列。每個 accepted request 只提交一個同 partition conditional `INSERT ... IF NOT EXISTS` LWT。Measurement 不執行 SELECT。

只有 LWT 回覆 `Applied` 後才發佈新 cache state。重複的已存在 request 回傳原結果，不做額外 wallet mutation。任何無法確認結果的提交錯誤都保留 `CommitOutcomeUnknown`，freeze 該帳戶並 global fail closed。不自動 retry。

```text
Credit/Debit input
  -> Service::submit -> account owner lock + enqueue
  -> worker_loop -> process_job
  -> ScyllaStore::commit (one conditional INSERT LWT)
  -> synchronous LWT persistence -> CL ONE acknowledgement
  -> publish cache only on Applied -> reply
After all replies
  -> verify_all -> verify_account / verify_one_account
  -> stop/inspect -> cleanup owned resources
```

## 啟動 gate 與執行順序

1. 執行 offline runner、unit/control tests 和設定 validation。失敗時停止，不建立 Scylla node。
2. 凍結 binary、runner、image digest、budget、job config 與來源 manifest。保存 source hash 和 config diff。
3. 執行 strict preflight。可用容量至少 `max(64 GiB, estimated requirement)`；CPU busy ≤10%；device busy ≤5%；available memory ≥32 GiB；AIO 和其他 profile gate 通過；須有三個連續 passing samples。
4. 建立單一 fresh owned node。驗證 CPU/memory limits、CPU affinity、image digest、RF1、`durable_writes`、Wallet consistency、periodic 設定和 `O_DSYNC=false`。
5. 保存 pinned source `force_sync` evidence 並驗證來源版本。若 evidence 缺少或不匹配，將 case 設為 invalid，停止，不進入 measured workload。
6. 使用 bounded setup concurrency 完成 seed/preload。Setup 不納入 measurement。確認 load 完整後才發出 ready event。
7. 執行唯一 S2/C512 workload。每個 user 順序送出 1,000 個 amount=1 的 Credit/Debit requests。
8. 最後一個 reply 後結束 measurement window。停止 stages metrics，drain service，完整驗證 cache、accounts 和 ledger。
9. 停止並 inspect node。只清理由本次 ownership manifest 確認的資源。保留 evidence、cleanup 和最終 report。

本需求不做 smoke、重校準、batch rerun 或 retry。若 strict gate、runtime profile、source evidence、service result、verification、metrics 或 cleanup 任何一項失敗，停止 workload，保存 failure evidence，並清理確認 owned 的資源。

## Strict preflight 與必備驗證

Strict preflight 記錄容量、CPU、device busy、available memory、AIO、profile 狀態與三個連續 passing samples。不得用 relaxed diagnostic preflight 代替正式 case gate。需要容量至少 `max(64 GiB, estimated requirement)`。

Service 必須回報 attempted、accepted、applied 和 replied 各 1,024,000。Credit/Debit 各 512,000。完整驗證 1,024 accounts 和 1,024,000 ledger rows。Measured SELECT 必須是 0；driver query delta 必須等於 1,024,000。Driver errors、retries、request timeouts、connection timeouts、unknown outcomes 必須為 0。

Pool target 與每次 sample 必須為 D=6。Worker busy/current/peak 不得高於 C=512。Required HDR samples、stages、CPU、RSS、cgroup、host diskstats、Prometheus shard CPU、commitlog、I/O queue、driver/server counters 和 runtime profile 都要通過各自 validity checks。

正常成功流程中，完成 shutdown、drain 和完整 verification 後才 cleanup。若失敗或中斷使完整 verification 無法完成，先保存原始錯誤及 partial evidence，再停止 node，並清理 ownership manifest 確認屬於本次的資源。不得因 verification 未完成而保留 Scylla node 或本次 owned data。Final audit 記錄 node、network 和 owned data 的狀態；不得刪除 ownership 未確認的資源。Failure artifacts 保留 partial result、original error samples、counters、source/runtime evidence 和 cleanup state。

## 測量與報告

Measurement window 從 clients 開始送出前到最後一個 client 收到 reply。保存 wall time、accepted/replied、RPS、end-to-end HDR、admission/queue/LWT stages、pool/current/peak、DB worker busy、driver counters、errors、process CPU/RSS、cgroup CPU throttling、host partition/whole-device diskstats、per-shard CPU、commitlog 與 I/O queue metrics。

Process/RSS/cgroup 與 host disk observer 以 1 Hz 保存 samples，並包含時間戳。保留 raw Prometheus 與 raw diskstats samples。Partition 與 whole-device counters 分開保存，不相加。Summary 必須分清楚 raw counters 與 derived rates/latencies。Whole-device flush await 不是單筆 LWT fsync latency。Disk busy、I/O queue 和 throughput 不可單獨證明物理裝置飽和。

定量比較只對照既有 [batch baseline](01-56.development-analysis-scylladb-calibrated-s2-concurrency-benchmark.md)：RPS 15,884.913190380918、E2E p99 171.704319 ms、LWT p99 50.036735 ms。不得合併 HDR，也不得把舊 run 當本次重複試驗。

報告需說明每種 commitlog mode 的設定、LWT synchronous persistence、force-sync evidence、實際 image/config/source hashes、strict gates、完整結果、cleanup 與限制。校準期間寫入頻寬曾偏離 107%；此測試仍共用 host 裝置且只有一次短測。不得由結果推論統計顯著性、steady-state、production SLA、每交易 fsync 次數、物理磁碟飽和或其他 workload 的耐久性。

Periodic profile 是單一診斷 pilot，不是正式 27-case matrix。所有 artifacts 儲存於本機 `target/`，最後報告連結實際存在的檔案。不要預先填入不存在的 job 路徑或結果。
