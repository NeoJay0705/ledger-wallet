## Case matrix 與命令形狀

`S=2` 固定為每 node 兩個 shards。`C` 同時表示 worker 數與 application CQL in-flight 上限。`P=ceil(C/50)` 是每 node、每 shard 的 data connections target。每 node connections 是 `2P`，全 cluster 為 `D=3×2×P`。

| Case | S | C | P per node per shard | Connections per node | D across 3 nodes | Users × requests/user |
|---|---:|---:|---:|---:|---:|---:|
| 1 | 2 | 128 | 3 | 6 | 18 | 1,024 × 1,000 |
| 2 | 2 | 256 | 6 | 12 | 36 | 1,024 × 1,000 |
| 3 | 2 | 512 | 11 | 22 | 66 | 1,024 × 1,000 |
| 4 | 2 | 1,024 | 21 | 42 | 126 | 1,024 × 1,000 |

每個 case 只執行一次，依 C 遞增。Pilot mode 不會自行套用 27-case formal gate；target-only supervisor 必須在每個 case 啟動前，使用既有 `strict_formal_preflight` 和該 case 的正式 workload estimate，檢查 host CPU、memory、device、disk 與輸出 filesystem。不得複製或放寬 gate。

每個 case 使用新 keyspace、新 owned node data。命令形狀如下，`C`、`P` 取自表格：

```bash
python3 benches/scylla_wallet.py \
  --mode pilot \
  --shards 2 \
  --workers C \
  --per-shard-pool P \
  --worker-routing round-robin \
  --replication-factor 3 \
  --read-cl 3 \
  --write-cl 3 \
  --users 1024 \
  --requests-per-user 1000 \
  --repeats 1 \
  --skip-build
```

在 reuse 既有 release binary 前，先確認實際 source files、Rust build inputs 與 approved binary hash 相符。啟動後固定 source/binary snapshots；不改 benchmark source 或 product code。Supervisor 為每個 case 保存 argv、strict preflight samples、PID、UTC 開始/結束、source/binary hashes、run/trial IDs 和 cleanup result。

## Runtime 與 workload 核對

啟動後確認三個隔離 node 都使用 pinned image `scylladb/scylla@sha256:333b9ab3a3214c7f98af100711c51df7f58964e8227e6d26050e889ebb216df1`，release 為 `2026.1.14`，S=2。核對 RF3、`durable_writes=true`、read/write CL `THREE`、serial CL `LOCAL_SERIAL`、`commitlog_sync=batch`、`commitlog_use_o_dsync=false` 和既有 write acknowledgement/fsync profile。

Runtime CPU affinity 必須核對每 node 的兩個 reactor：A 對應 CPU `0,1`、B 對應 `2,3`、C 對應 `4,5`。service、load、monitor 使用 CPU `6,7,14,15`。啟動前保存 `lscpu` 核對；執行時保存 reactor thread affinity 和 client process affinity。每個 node 設定 8 GiB memory，cgroup limit 10 GiB。

每 case 在 start gate 前建立 1,024 筆初始 state 並 preload 到 memory。Measurement window 中，1,024 users 各送 1,000 筆 amount 1 的 Credit/Debit 交替 requests。同一 client 等待 reply 後才送下一筆。Round-robin dispatch 不解除 account owner lock：同帳戶交易在 cache compute、LWT 與 acknowledgement 間依序處理。

每個 accepted request 必須對應一個 conditional `INSERT ... IF NOT EXISTS`，measured SELECT 數為 0。Applied ack 後才更新 cache。預期每帳戶 1,000 筆 Applied、最終 balance 100、version 1,000、logical clock 1,000 及 1,000 ledger rows。全 case 預期 1,024,000 requests/replies/ledger rows；逐帳戶比較 cache、static state 與完整 ledger。

## 驗收與 stop rule

| 驗收面向 | 每 case 要求 |
|---|---|
| Gate / metrics / source correspondence | Strict preflight 與 required metrics 有效；hash 符合凍結快照 |
| Effective profile | S=2、RF3、read/write `THREE`、serial `LOCAL_SERIAL`、commitlog profile 相符 |
| Pool | 每 node `2P`、total `D=3×2×P`；pool ready、socket audit 無 mismatch |
| Requests | 1,024,000 accepted、applied、replied |
| Driver accounting | 1,024,000 query delta、0 measured SELECT |
| Errors | 0 storage/application errors、retries、request/connection timeouts、unknown outcomes |
| Verification | 1,024 accounts、1,024,000 ledger rows 全部符合預期 |
| Cleanup | 本 trial owned containers、network、data 全部 clean |

任一 case 出現 preflight fail、CLI/profile invalid、failed/relaxed/invalid status、required metrics 缺失、driver mismatch、correctness failure 或 dirty cleanup 時，不啟動後續 case。保留所有 artifacts 和 unknown outcome；不 retry、不延長 deadline、不降 CL、不調整 pool 或 workload。

## 測量資料與比較限制

保存完整 measurement-window RPS、成功 Applied RPS、E2E p50/p95/p99、各 stage histogram、CQL in-flight peak、worker busy/idle、driver deltas、CPU、I/O、connection min/max/samples、每 node/per shard commitlog flush、bytes、cycle、allocation、pending counters 與 sampling offsets。若 trial 部分失敗，partial throughput 不作為有效 case 效能值。

Scylla 同一 host/SSD 上運行三個 node。`S=2` 使每 node reactor CPU 數加倍；固定同一 C/P 時，每 node data connection 也由 `P` 增至 `2P`，而每 node 8 GiB memory limit 不變。因此每 shard 可用 memory 減少。與 S=1 結果比較只能描述整體 shard/CPU/pool profile 的變化，不能稱為純 CPU scaling。

Commitlog counters 是 node/shard 層統計，不是 wallet transaction 或 fsync 次數。Paxos LWT 可能有額外內部讀寫。`commitlog_sync_batch_window_in_ms=10000` 是設定值，不表示每筆請求等待固定 10 秒。單次 pilot 不證明穩態、統計顯著性或 27-case formal completion。

## Execution flow

```text
input
  -> run_clients
  -> run_client (one account; wait for each reply)
  -> Service::submit
  -> account owner lock
  -> worker_loop (round-robin shared pool)
  -> process_job
  -> read cached AccountState and compute next result
  -> ScyllaStore::commit
  -> one conditional INSERT ... IF NOT EXISTS
  -> LOCAL_SERIAL / regular CL=THREE / durable acknowledgement
  -> publish cache after Applied acknowledgement
  -> reply

after replies
  -> drain service and verify all account caches, static states and ledger rows
  -> retain CLI Session for runner connection/socket audit
  -> release finish gate; CLI exits and closes Session
  -> cleanup only this case's owned containers, network and data
  -> save case evidence and update matrix summary

unknown outcome or invalid case
  -> freeze affected account and fail closed globally
  -> settle accepted work and preserve partial evidence
  -> stop launching later cases; clean owned resources; do not retry
```
