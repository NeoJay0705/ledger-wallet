## 第一次啟動結果

第一次啟動使用 job `calibrated-single-node-rf1-s2-periodic-c512-20261013T012925Z`，run `run-20261013T015038Z-0010535e`。Strict preflight 通過。Runtime REST probe 回報 `commitlog_sync=periodic`、period=10000 ms、`O_DSYNC=false`；pinned-release LWT source evidence 也通過。

`cqlsh SELECT JSON` 的 pretty output 對 `commitlog_sync` 字串多加一層反斜線跳脫。現有 parser 無法把這個值正確解碼。Parser 將 `system.config` 的正規化結果記成 null。這是 parser 結果，不是 Scylla 回傳資料庫 NULL。

嚴格 runtime gate 要求 REST 和 `system.config` 都驗證 periodic profile。因 `system.config` 未驗證成功，gate 正確地 fail closed。這是 setup/config probe failure；不能記為 Wallet 交易錯誤，也不能算作性能測量。

## Probe 修正

下一次 gate 同時保留兩種證據：REST 原始輸出與 `system.config` 原始 probe output。只對 `commitlog_sync` 增加 plain CQL 查詢：

```sql
SELECT name, value FROM system.config WHERE name = 'commitlog_sync';
```

Plain probe 必須驗證 process exit code、欄位名稱、欄位順序、回傳一筆資料、name 精確等於 `commitlog_sync`，再將 value 限定解析為 `batch` 或 `periodic`。保留原始 stdout/stderr 與解析後欄位。

只修正此設定的 probe。不得對任意欄位做通用 unescape，不得忽略 parse error，也不得只用 REST 作替代 gate。Period、`O_DSYNC`、pinned image、source hash 與 LWT force-sync evidence 的檢查保持原樣。

| 必要 gate | 新 case 必須觀察到的值 |
|---|---|
| REST `commitlog_sync` | `periodic` |
| `system.config` plain CQL | 一筆、名稱正確、enum `periodic` |
| `commitlog_sync_period_in_ms` | `10000` |
| `commitlog_use_o_dsync` | `false` |
| Pinned-release source evidence | 驗證有效，且包含 LWT `force_sync` 路徑 |

任何值缺漏、重複、解析失敗或與 profile 不符，都在 Wallet CLI 啟動前停止 case。不得將 gate 放寬為 warning。

## 後續執行順序

1. 以第一次 run 的原始 evidence 重播 parser，並加入 JSON escaped enum 和 plain CQL valid/invalid fixtures。
2. 執行 runner full suite、compile、exact dry-run 與 pinned source evidence replay。保存所有輸出和新的 source hash。
3. 將 parser change、目前 source snapshots、已記錄的歷史 hashes/change summary 和 validation result 提交 root review。舊 source bytes 不可用，因此不宣稱完整 source diff。Root review 後凍結新 job inputs。
4. 建立新的 fresh owned job。不得重用第一次 run 的 keyspace、資料、容器或 network。
5. 在新 job 內執行 external strict preflight。只有 preflight 通過後才建立 fresh node，再驗證 REST、plain `system.config`、period、`O_DSYNC`、image digest 和 source evidence。
6. 全部 gate 通過後，只執行一次同規格 1,024,000-request periodic case。這不是 app retry；也不重跑或重寫第一次 setup failure。
7. Drain、完整驗證、停止並 inspect node，再清除 ownership 確認的資源。保存新 job provenance、runtime probe、service result、verify、metrics 與 cleanup。

若下一次 runtime gate 仍失敗，不啟動 Wallet CLI，保留失敗 evidence 並清理 owned resources。若 gate 通過後 measured workload 真正失敗，也停止，不 retry。所有結果都用新的 job/run path 保存。

第一次 run 保留了當時記錄的 hashes 和 end-hash match 狀態，但舊 source bytes 不可用。本次不聲稱能產生完整歷史 source diff。修正後的 job 保存自身 source、binary、config 和 probe hashes；只有可取得的實際 source bytes 才做逐檔 diff。

## Profile 與結果界線

後續 case 沿用 [01-57 設定](01-57.raw-requirement-scylladb-periodic-s2-c512-benchmark.md)：N=1、RF1、read/write `ONE`、serial `LOCAL_SERIAL`、S=2、C=512、P=3、D=6、1,024 users × 1,000 requests。Periodic period 為 10,000 ms，`O_DSYNC=false`。Binary、image 和 budget 依 freeze manifest 核對。

LWT 在此 Scylla release 的所有 commitlog modes 下仍同步持久化。Periodic setting 不表示沒有 fsync，也不保證禁止 group commit。報告只能說明本次 pinned release、實際 config 與 workload 的量測結果。

第一次 run 沒有 Wallet request、measured window 或 valid performance metrics。RPS、latency、LWT stage 和 account verification 均為「未測量」，不得填 0。第一次 run 的 observer samples 只能記錄 setup window，不得充當測量窗 samples。

```text
first attempt
  REST reports periodic -> cqlsh JSON double-escapes enum
  -> parser returns null -> system.config gate fails closed
  -> no Wallet CLI -> preserve setup evidence -> clean owned resources

correction and new attempt
  offline replay + negative fixtures -> root review -> freeze new inputs
  -> create fresh job -> external strict preflight -> create owned node
  -> REST + plain system.config + period/O_DSYNC/source runtime gates
  -> one 1,024,000-request case -> verify -> cleanup -> report
```
