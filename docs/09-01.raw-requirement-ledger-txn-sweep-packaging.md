# 09-01 raw requirement — 整理 TiDB／PG ledger txn 掃描測試並納入本 repo

來源：本機工作目錄（非本 repo）中的 R1 txn benchmark 專案；此需求把其測試案例、測試程式、監控資料整理進本 repo（public）。

## 範圍
1. 測試案例（對應編號文件 04–08）：
   - 04 TiDB R1 txn（帶 before/after，對應 `benchmarks/pg-ledger-txn` 的 PG R1），CPU4／CPU8、no RF、預切 256 region。
   - 05 batch-max 掃描（256 queue、256 連線）。
   - 06 連線數掃描（batch 50／100，連線 4–256）。
   - 07 固定連線 batch 掃描（PG CPU4／CPU8 16 連線、TiDB CPU4 16 連線、TiDB CPU8+ 16／32 連線）。
   - 08 TiKV 6／tidb-server 8 與 TiKV 4／tidb-server 4 補測（16 連線、batch 2000／4000／8000）。
2. 位置：新目錄 `benchmarks/ledger-txn-sweep/`，自包含 crate（PG 與 TiDB 兩個 client、全部腳本與測試）。`benchmarks/pg-ledger-txn/` 不動。
3. 資料：只放彙整表與各測試點的關鍵檔案，不放逐 250 ms 取樣的大檔、`_invalid/` 與 smoke；表上數字須能追到來源；報告產生器與稽核須能用已發布資料重現文件。
4. 文件：`docs/04-xx`…`08-xx`（raw-requirement／development-design／development-analysis）與 `benchmarks/ledger-txn-sweep/README.md`（情境監控表、測試與重現方式、限制）。README.md 根目錄加一行連結，其他既有檔案不動。
5. 驗證：不重跑 benchmark；Python 全套測試、`cargo test`、各 driver `--dry-run`、報告重現、連結檢查。不 `git commit`。

## Public repo 限制（新增）
- 不得含真實憑證、token、個人或主機識別（家目錄路徑、使用者名稱、主機名稱）。測試容器使用的僅限本機拋棄式密碼（`postgres`、`gate2d`）須在 README 明確標註，如 `benchmarks/pg-ledger-txn` 所做。
- 發布前以程式掃描全部新增檔案並留下掃描輸出作為證據。
- 沒有證據的敘述不寫；沒量的標「沒量」。
