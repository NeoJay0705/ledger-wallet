## 固定的比較形狀

每個 case 只執行一種資料庫。ScyllaDB 和 PostgreSQL 輪流使用同一 host、ext4 filesystem、`/dev/sdb2` 資料路徑、database CPU set、container memory/swap profile 和 `/dev/sdb` cgroup I/O caps。所有資料庫背景工作都留在 DB container 的 cgroup 中。

| 資源 | ScyllaDB | PostgreSQL |
|---|---|---|
| CPU affinity | `0,1`，不設 CPU quota | `0,1`，不設 CPU quota |
| Container memory / swap | 10 GiB / 0 extra swap；Scylla node memory 8 GiB | 10 GiB / 0 extra swap |
| Device cap (`8:16`) | read 403,631,184 B/s，write 152,226,096 B/s，read 24,497 IOPS，write 23,500 IOPS | 同值 |
| Data filesystem | `/dev/sdb2` (`8:18`), ext4 | 同一 bind-data filesystem |
| Network / ownership | 每 case 新 network、data path 和 owner/nonce labels | 每 case 新 internal bridge 和 bind-data path；host client direct-IP:5432，no published ports；trust 僅在本 run dedicated network |

PostgreSQL image 固定為 `docker.io/library/postgres@sha256:afc7e2d441324c0388fa80c3d24f733b4194a4eb7f47dd8ee2b08eb1a24a647c`，本機 qualified image ID `sha256:2e182ed2ff8f5d0835353864264437a26dffc542a9a6c677ec495aa54e491627`，server version `18.6 (Debian 18.6-1.pgdg12+2)`。2026-10-13 的 PostgreSQL [versioning policy](https://www.postgresql.org/support/versioning/) 列 18.6 為 18 的 current minor，版本發布資料見 [18.6 release notes](https://www.postgresql.org/docs/release/18.6/)。PostgreSQL 18 官方 image 的 bind mount 目標是 `/var/lib/postgresql`，`PGDATA=/var/lib/postgresql/18/docker`；host parent 為可 traversal 的 mode `0755`，由官方 entrypoint 建立並限制 PGDATA 權限。Image tag 僅供 pull/檢查使用，實際執行必須用 digest reference 並比對 image ID。

固定 PostgreSQL startup settings 為 `shared_buffers=2GB`、`work_mem=4MB`、`maintenance_work_mem=256MB`、`autovacuum_work_mem=64MB`、`max_connections=100`、`fsync=on`、`synchronous_commit=on`、`full_page_writes=on`、`wal_sync_method=fdatasync`、`commit_delay=0`、`wal_level=replica`、`checkpoint_timeout=5min`、`max_wal_size=1GB`、`autovacuum=on`、`track_io_timing=on` 和 `track_wal_io_timing=on`。啟動後讀回全部設定；任何差異都 fail closed。

PostgreSQL client 使用 database `walletbench`，pool size 為所選 D，CLI 固定 C=512。每個 pool session 連線後核對同步提交和 WAL 安全設定、`pg_is_in_recovery=false` 及無同步 standby 設定。SQL snapshot 位於 [`postgres_wallet.sql`](../benchmarks/scylla-wallet/sql/postgres_wallet.sql)，SHA-256 為 `7a26158b91785a0a8eb8da2950608d662f530eeecab5fe584535506da010e5f1`；先前 live qualification CLI SHA-256 為 `b507e1f112a30ea8ffcf4bd2d185ee4ec485a858edcc8832bdafabe67b9a3fe2`，formal-campaign candidate CLI SHA-256 為 `02ddf0f843ab8a7a15d2f20cc3ed35f6d7661fcbd1d4e4141250672fcba7e555`。Migration 在本 run schema 建立 `accounts` 和 `ledger`，兩個 key 為 non-negative `BIGINT` 且分別命名 `accounts_pkey`、`ledger_pkey`；balance/amount/resulting balance 為剛好 8 bytes 的 BYTEA。`wallet_commit` 接受 wallet operation/result fields，嘗試插入唯一 `(account_id, tx_id)` ledger row；新 row 時更新一筆 account row，row count 非 1 即 raise 並回滾 statement transaction。Duplicate path 回傳 current account state 和原 ledger business fields，由 service 比對 incoming operation/amount/result fields 並拒絕 content conflict。既有 live qualification 證據只適用先前 binary；新 candidate 尚未 live-qualified。每次 formal case 前均保存 source/binary/SQL/config/image/caps snapshots 和 hashes。

## Wallet commit 語意

同一個 Wallet service 和 account owner/cache 路徑同時服務兩個 backend；每個 case 只選其中一個 backend。新 request 不先作獨立 DB read。PostgreSQL client 對預先 prepare 的 `wallet_commit` 發出單一 statement call，由 server 端一個隱式 transaction 原子處理 ledger 和 account。Client 只有在 PostgreSQL command stream 完全 drain 到 `ReadyForQuery` 後才回覆 request；實際 Rust client 已通過 host-to-container-IP direct connection 的 integration qualification。

所有 Wallet `u64` amount/balance 以 8-byte BYTEA 保留完整範圍。Ledger key 為 `(account_id, tx_id)`。新請求不論 applied 或 business rejection 都寫一筆 ledger row；applied 改變 balance，insufficient-funds、overflow、invalid-amount 保留 balance，但 version/write_clock 前進，並在 durable acknowledgement 後同步 cache。相同 key 與內容的 duplicate 回傳原始結果、不再次更新 account/cache；同 key 不同內容是 conflict；missing account 必須使 ledger/account 兩項都 rollback。Constraint/function failure、已確認 rollback 或 unknown commit 不發布未提交 state；unknown commit 會 freeze account 並 fail closed。

Unknown commit outcome 會 freeze 對應 account，並使 workload fail closed；measured run 不自動 retry、reconnect、pipeline 或重送未知操作。DB pool connection exclusive checkout；每個 connection 同一時間至多執行一個 statement。此設計把 pool wait 獨立量測，但仍包含在 end-to-end latency 和 workload RPS 時窗內。

## Calibration 和正式 cases

Service/load client 使用 C=512、queue capacity 50,000、setup concurrency 6；CPU affinity 為 `6,7,14,15`。Scylla 的既有 calibrated scheduler budget 定義在 `target/scylla-wallet/iotune-calibration-jobs/20261012T133244Z-6180f531/budget/io_properties.yaml`，SHA-256 `12bf0b79c4520ca6d00183ca14b87d321b9221b687cc6e889619876f5b87b2bf`；Git 內保留的相同來源內容為 [equal-resource profile `io_properties.yaml`](../benchmarks/scylla-wallet/profiles/equal-resource-20261013/io_properties.yaml)。兩個 backend 共用的 Docker host-I/O caps JSON SHA-256 為 `c95f1a8ba5204051fe48e61bd05333ef10122f1b9e0ad78c8a41ad1bbf9b87fc`。資料包含 1,024 accounts，每個 account 1,000 個 sequential operations，共 1,024,000 requests；Credit/Debit 各 512,000，amount=1。每個 account 同時只有一筆未完成 request。

先執行 PostgreSQL D=16、32、64 各一個 fresh 1,024,000-request calibration case。只用通過 runtime/capacity/correctness/result/cleanup gates 的 case 選擇 D。取有效 RPS 最高者的最小 D，且該 D 的有效 RPS 至少達到最高有效 RPS 的 95%。Calibration 不加 D=6；Scylla D 固定為 6。

選好 D 後，執行六個 fresh full cases，順序固定為 `Scylla, PostgreSQL, PostgreSQL, Scylla, Scylla, PostgreSQL`，每 backend 三次。所有 case 各自 seed、full verify、收集 metrics，之後只清理由該 case owner/nonce 標記且 inspect 確認的資源。三個 calibration 加六個 full cases 共九個 case；任何一次失敗均保存 immutable evidence、停止該次且不得用 app retry 補跑。未通過的 run 不加入有效 RPS 或挑選門檻計算。

## 時鐘與觀測

測量窗由第一個 client request 開始，到最後一個 client reply 完成。此窗包含 admission、owner ordering、service queue、PostgreSQL pool wait 和 SQL latency。另行報告 pool wait、SQL latency、end-to-end latency、errors/timeouts/unknown outcomes 和 throughput。Setup、seed、full verification、checkpoint/drain 和 cleanup 位於該 window 外；checkpoint/drain 時間單獨報告，不加到 workload RPS。

PostgreSQL 每 case 保存 workload 前後的 `pg_stat_io` WAL object writes/fsync/timing、`pg_stat_wal` bytes/FPI、`pg_stat_activity` wait events、`pg_stat_database` transaction counters、PG18 checkpointer stats 和 autovacuum stats。Host diskstats 以 1 Hz 收集，partition 與 whole device 分開記錄且不相加；cgroup IO stats 與 IO cap 讀回一起保存。Container cgroup CPU 和 memory 包含 page cache；不能累加 PostgreSQL backend RSS 估算實際 server memory，因 shared mappings 會重複計數。flush counters 是 block-layer/DB observability，不是每筆 Wallet transaction 的 fsync count。

儲存 checkpoint/drain 時間及其 stats window，確保明確不在 throughput clock 內。短閉環 run 不代表 steady-state，也不能推出硬體極限。`fsync=on` 和同步 commit 代表 PostgreSQL 要求 OS/device flush acknowledgement，不代表本 qualification 已測試斷電後保存能力。

## Network 與安全邊界

已通過的 host-native integration qualification 使用新建 internal bridge、無 host-published port，並由 host 直接連到該 run 的 container IP `172.24.0.2:5432`。`POSTGRES_HOST_AUTH_METHOD=trust` 只在該短生命期、dedicated internal network 使用。Runner 將沿用 direct-IP/internal-bridge/no-published-port 形狀；root final freeze review 前不開始正式 calibration 或 full cases，也不得把 network-scoped trust profile 移用到其他用途。

## Failure 和 cleanup

Strict preflight、image digest/ID、server version、`SHOW` profile、`pg_is_in_recovery`、pool setting、cgroup CPU/memory/swap/IO、filesystem device、DB statistics availability、full correctness、latency/error schema、ownership labels 和 terminal cleanup 都是 fail-closed gates。失敗時不放行 measured start、不重試 case、不覆寫任何 prior attempt。保留 stdout/stderr、inspect、container logs、metric snapshots、configuration 和 failure 原因。

清理只針對本 run unique nonce 且 owner label 相符的 container/network，及 bind path 與 inspect mount、manifest 都相符的目錄。容器先停止並保留 logs/inspect，再移除。PGDATA 由 Docker helper 清除前檢查 exact host path、PG18 layout、ownership、mount 和 directory manifest；其他 path 或 ownership 不清楚時保留並記錄，不作寬範圍 `docker prune`、host-global filesystem/kernel 操作、drop caches 或 sysfs 修改。
