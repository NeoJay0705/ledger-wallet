# Wallet 同步持久化基準測試：歷史證據封裝設計

日期：2026-10-14。需求編號：01。文件序號：67。

## 目標與範圍

ScyllaDB、PostgreSQL 的設計、qualification 與結果文件保留各次 run 的原有結論和數值。本設計處理證據在 Git 和本機 archive 的保存方式，讓新 checkout 不需要預先存在 `target/` 也能閱讀主要結果、來源 hash 與封存索引。

Git 保存文件、少量可直接檢閱的原檔、明確標記為衍生的 JSON 摘要、完整原始檔案 manifest 和 archive metadata。完整 原始證據 保存於 Git 外的本機 archive；該路徑不是共用下載網址。不得將原始失敗案例與有效 RPS 合併，也不得把歷史三 CQL profile 併入 memory-LWT 結果。

## Scylla 證據的保存邊界

來源是 `target/scylla-wallet/`。外部 `scylla-wallet-evidence.tar.gz` 保留 4,061 個檔案，來源總大小 5,407,757,600 bytes。壓縮檔大小 4,367,723,502 bytes，SHA-256 為 `0d4f5a0aa109ea4add3fdcbb7fa7c061fe0845bf258e820cf50677e03297aa4b`。完整 `original-files.csv` 為 1,363,020 bytes，SHA-256 為 `92f36e42f0c069667845e5ed848278a9d2a020063689ca60394bb434a1a8c3b4`；`archive-metadata.json` SHA-256 為 `0b63c7cae447d1723ab183d26865b59483886ece04b750e96755c0fc0fbcd037`，記錄相同檔案數、原始位元組數、archive 與 manifest hash。兩個 metadata 檔在 Git package 及外部 archive 都有保存。

只排除 `target/scylla-wallet/` 頂層編譯目錄 `debug/`、`release/`、`build/`、`incremental/` 及根目錄 `.rustc_info.json`。例如 `formal-jobs/.../input-snapshot/build/` 是歷史輸入快照，仍按原路徑封存。Job 的 frozen binary、source、設定、錯誤輸出與 run artifacts 仍是歷史證據；它們不因副檔名或名稱像 build output 而排除。索引中的 `target/scylla-wallet/release/ledger-wallet-scylla-bench` 是頂層 release 編譯產物，不是 frozen job snapshot，故未放入原始 archive manifest。若文件提到此檔，索引明示該檔未封存；其 SHA 只由保存的測試記錄佐證。

Git 小包收錄文件實際引用且適合逐檔檢閱的小型 `service/result.json`、summary/configuration CSV 與 JSON、非空且有診斷價值的 log/config/output，以及大型 `result.json`、`run-result.json`、`runner-result.json` 的選定欄位摘要。大型 JSON 摘要保留 status、workload/profile、驗證、錯誤、請求數、RPS/latency scalar、原始路徑、原始 bytes 和 source SHA-256；它不是原始檔替代品。摘要以 `.summary.json` 命名並由 archive index 連到原始 member。19 個被引用的空 stdout/stderr/log 不存 Git 副本；索引仍列出原始 0 bytes、空檔 SHA-256 和 原始封存 member。`prom.gz`、大型 metrics/log、完整 snapshots 與未選入 Git 的其他檔案均可從原始 archive 還原。

Summary CSV 和小型 service result 是歷史表格的直接依據；大型 runner/run result 只作狀態和完整性輔助。若 service result 表示 failure 或 partial workload，文件保留其失敗上下文，不把它計作有效 RPS。三 CQL 失敗紀錄和 memory-LWT 有效結果在路徑與摘要中各自分開。封存不改任何歷史數字或 run 結論。

Wallet DB compare 使用另一份原始封存。`docs/01-63` 至 `01-65` 連到 `benches/data/wallet_db_compare/run-20261013T124123Z-3216cf07f3/README.md` 的 `#raw-archive` 和 `#original-evidence-lookup`。該 archive 有 2,033 個檔案、解壓後 176,228,422 bytes；壓縮檔大小 45,614,492 bytes，SHA-256 為 `d0977b40c7b1f75dadc57ede978538669941aff76bc2b446f29324b6970c3c19`。Git 內 `original-file-manifest.csv` 為 376,286 bytes，SHA-256 為 `1a119472ce6c01f9566e649d6c731561a80b55a9626a929aa5d7fddcd1419a2f`。來源、摘要與重新驗證流程如下：

```text
wallet-db-compare original target tree + original-file-manifest.csv
  -> build_bundle
```

## 封裝與還原流程

`benches/archive_scylla_evidence.py` 使用下列實際函式處理來源、archive 與驗證：

```text
pack command
  main
    -> pack_evidence_archive
       -> _pack_evidence_archive_locked
          -> create_original_manifest
             -> scan_evidence_files
                -> is_evidence_path
          -> write_manifest
          -> create tar.gz (top-level compiler output excluded)
          -> verify_evidence_archive
       -> publish archive, manifest, metadata without overwrite

verify command
  main
    -> verify_archive_metadata
       -> verify_evidence_archive

extract command
  main
    -> extract_evidence_archive
       -> verify_evidence_archive (paths, duplicates, file count, sizes, hashes)
       -> extract manifest-listed regular files to a temporary tree
       -> verify_extracted_tree (no symlinks, missing files, extras, or hash mismatch)
       -> rename verified tree into the new destination
```

Archive root 固定為 `scylla-wallet/`。Manifest path、tar member path 和 hash 都須對應；path 不可走出 archive root，manifest 與 tar 不可有重複檔名。Pack 遇到已存在的 archive、manifest 或 metadata 即拒絕覆蓋。Extract 拒絕 symlink destination 或既有的 `scylla-wallet/` tree；先在 destination 下建立暫存目錄，完整驗證後才 rename。驗證只讀取檔案，不啟動 DB 或 benchmark。

新 checkout 可以直接檢閱 Git 小檔、摘要、source manifest 與索引，不需 `target/scylla-wallet/`。被逐位元組複製的歷史 report 保留原始內容，其中原有相對連結仍可能指向 target 路徑；這些檔案供歷史脈絡查閱，不是 canonical link index，應以 package index 對照來源。Git 內的 01-40 source snapshot 有兩個相對連結指向未複製的歷史同目錄文件；來源仍可由原始封存索引錨點 `#source-03ef4e3dfa6afaf4` 與 `#source-95d61aecd5faeba7` 還原。要還原完整 raw files，必須在可讀取 `/home/neojhou/benchmark-archives/ledger-wallet/scylla-wallet/` 的主機執行：

```bash
python3 benches/archive_scylla_evidence.py verify
python3 benches/archive_scylla_evidence.py extract --destination /tmp/scylla-evidence-restored
```

沒有這份本機外部 archive 時，文件不宣稱 raw files 可由 Git 或網路取回；索引仍供查詢原始路徑與 hash。

## 文件 hash 與驗證

Root `.gitattributes` applies `-text` only to the packaged evidence trees, equal-resource fixed-hash profile files, and JSON runtime fixtures, so clone `core.autocrlf` cannot rewrite their bytes. The Scylla `original-files.csv` retains its valid CRLF encoding and recorded SHA-256; the copied evidence is checked by size and SHA. The single-command whitespace check uses `cr-at-eol` for these CSVs while keeping the other whitespace checks enabled:

```bash
git -c core.whitespace=blank-at-eol,blank-at-eof,space-before-tab,cr-at-eol \
  diff --cached --check -- . ':(exclude)benches/data/scylla_wallet/artifacts/**'
```

Job `input-snapshot/` 內的文件 SHA 是建立 job 時的歷史輸入 hash。測量後的文件增加摘要、證據連結和 archive index，因此新版本文件的 SHA 已改變；本 package 不宣稱目前 wrapper-edited Markdown 仍與歷史 source snapshot hash 相同。Runner、服務與 benchmark 數字均以原始 evidence 記錄為準。

本封裝的離線測試為 `python3 -m unittest discover -s tests -p test_scylla_evidence.py -v`：9 項通過，涵蓋 top-level build-output 排除與 nested snapshot 保留、封存/manifest hash 往返、錯誤或重複 tar member、拒絕覆蓋、拒絕 symlink/existing destination、抽取目錄 symlink 驗證、大型 JSON 摘要欄位，以及不依賴 `target/` 的 Git 小檔 SHA/大小、summary source manifest 和 qualification source-manifest 核對。`py_compile` 亦通過。原始 archive 的 `verify` 已逐 member 核對 4,061 個檔案與全部 hash。這次沒有執行資料庫、Scylla/PostgreSQL benchmark 或外部 qualification script。

本輪 Git 第 1 至第 3 組的 Rust source 已逐檔通過 rustfmt；repository-wide `cargo fmt -- --check` 仍報 7 項既有差異，屬於該範圍外的其他 Rust 檔案。本次證據封裝不修改 Rust source，也不以全域差異掩蓋逐檔結果。
