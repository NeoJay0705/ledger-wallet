# ScyllaDB Wallet 記憶體狀態 LWT：RF3/CL3 雙 shard 並發與連線池掃描需求

日期：2026-10-12。
目標：RF3/CL3 雙 shard 下的並發與 data connection pool 掃描。
需求編號：01。文件序號：48。
狀態：授權四個單次 pilot cases；結果記錄於 01-50。

本需求沿用 [01-45 RF3/CL3 單 shard 需求](01-45.raw-requirement-scylladb-memory-lwt-rf3-s1-concurrency-benchmark.md)、[01-46 單 shard 設計](01-46.development-design-scylladb-memory-lwt-rf3-s1-concurrency-benchmark.md) 與 [01-42 memory-state LWT 需求](01-42.raw-requirement-scylladb-memory-lwt-benchmark.md)。本次固定每 node 兩個 shards，掃描四個 worker/pool 組合。交易、資料表、LWT、RF/CL、commitlog、deadline、retry、監控及 owned cleanup 契約不變。

## 目標與範圍

執行四個 RF3、read/write CL `THREE`、LWT serial CL `LOCAL_SERIAL` 的雙 shard pilot cases。每個 case 只執行一次，依 C 由小到大順序執行。這是 custom pilot，不是既有 27-case formal matrix；即使四個 case 都通過，也不代表 `formal_complete`、穩態效能或統計結論。

每個 case 建立新 keyspace、三個新 owned nodes 與新的 owned data。每個 case 前都要獨立通過 strict preflight。任一 case 未通過、驗證失敗或清理不完整時，停止剩餘 cases，不 retry。

先前 S=1、C=512 的失敗不取消這組使用者已授權的 S=2 sweep；每個 S=2 case 依本文件條件獨立 gate。S=1 結果只作為已記錄的 profile 對照，不作為改變本次工作負載或驗收條件的理由。

三個 ScyllaDB nodes 使用既有 pinned image `scylladb/scylla@sha256:333b9ab3a3214c7f98af100711c51df7f58964e8227e6d26050e889ebb216df1`，版本 `2026.1.14`。沿用 `wallet-memory-lwt-v1`、單一 shared Session、每筆一個 conditional `INSERT ... IF NOT EXISTS` LWT，以及 measurement window 零 SELECT。沿用既有 commitlog batch fsync acknowledgement、`commitlog_use_o_dsync=false`、deadline 與 no-retry 行為。

## Workload 與預期資料

每個 case 使用 1,024 個 accounts，每個 account 執行 1,000 個 requests，共 1,024,000 筆。每筆交易金額為 1，Credit 與 Debit 交替；client 等待目前 request 的 reply 後才送下一筆。同帳戶交易由 owner lock 序列化，worker dispatch 使用 round-robin shared worker pool。

| 項目 | 每 case 的預期值 |
|---|---:|
| Accounts | 1,024 |
| Requests per account | 1,000 |
| Total requests | 1,024,000 |
| Initial balance | 100 per account |
| Outcomes | 1,024,000 `Applied` |
| Final balance | 100 per account |
| Final version / logical clock | 1,000 / 1,000 per account |
| Ledger rows | 1,000 per account、1,024,000 total |

每個帳戶必須完整驗證 cache、static state 與 ledger。不得用全庫總 row count 取代逐帳戶驗證。每帳戶 1,000 row 的既有 verification limit 正好符合此工作負載。

## 雙 shard worker 與 pool cases

`S` 是每 node 的 shard 數，固定為 2。`C` 是 worker 數與應用層 CQL in-flight 上限。`P=ceil(C/50)` 是每 node、每 shard 的 data connection target。每 node connections 為 `S×P=2P`；三 node 總連線 `D=3×S×P`。

| Case | S | C workers | P per node per shard | Connections per node | D across three nodes |
|---|---:|---:|---:|---:|---:|
| 1 | 2 | 128 | 3 | 6 | 18 |
| 2 | 2 | 256 | 6 | 12 | 36 |
| 3 | 2 | 512 | 11 | 22 | 66 |
| 4 | 2 | 1,024 | 21 | 42 | 126 |

`C` 與 `D` 分開記錄。Pool-ready、每 node/per-shard target、`system.clients` 分類、socket samples 與 before/after audits 必須符合設定，且沒有非目標連線。

## ScyllaDB 與 host profile

| 設定 | 值 |
|---|---|
| Node count | 3 個隔離 nodes，共用同一 host 與 SSD |
| ScyllaDB | pinned `2026.1.14` image |
| Shards | 每 node `S=2` |
| Memory | 每 node 8 GiB；cgroup limit 10 GiB |
| Replication | RF=3、`durable_writes=true` |
| Wallet read / write CL | `THREE` / `THREE` |
| LWT serial CL | `LOCAL_SERIAL` |
| Commitlog | `commitlog_sync=batch`、`commitlog_use_o_dsync=false` |
| Write acknowledgement | commitlog batch fsync 後 |
| Retry / deadline | 沿用既有設定，不 retry、不延長 deadline |
| Routing | round-robin；owner lock 保持每帳戶循序 |

維持既有 CPU affinity 和 SMT：node A 的兩個 shard 使用 CPU `0,1`，node B 使用 `2,3`，node C 使用 `4,5`；service、load 與 monitors 使用 CPU `6,7,14,15`。啟動前以 `lscpu` 核對實體核心配置。Host/SSD 為共用環境；不更改 host 全域參數。

Measurement 前完成 seed 與 memory preload。Measurement window 內，每個 accepted request 使用一個 LWT CQL request，measured SELECT 數為 0。LWT/Paxos 與 commitlog group commit 可有額外內部工作；CQL query、flush、cycle、allocation counters 不等於每筆交易各自完成一次 fsync。

## 驗收、停止條件與證據

Case 只有同時符合以下條件才能標示 `passed`：

- 每 case strict preflight、required metrics 與 source/binary correspondence 均有效。
- 三個 node、image/version、S=2、schema、RF3、`durable_writes=true`、read/write `THREE`、serial `LOCAL_SERIAL` 均符合設定。
- 每 node 連線為 `2P`，cluster data connections 為 `D=3×S×P`；pool ready、socket 穩定且無 mismatch。
- 1,024,000 requests 全部 accepted、applied 並收到 reply；driver query delta 為 1,024,000，measured SELECT 為 0。
- errors、retries、request timeouts、connection timeouts 與 unknown outcomes 均為 0。
- 1,024 個帳戶均驗證成功；每帳戶有 1,000 筆 ledger rows，最終 balance/version/logical clock 符合預期。
- 本 trial 的 owned containers、network 和 data 全部 clean。

任何 preflight、trial、CLI/profile、metrics、driver accounting、verification 或 cleanup 失敗時，停止後續 cases。保留 error samples、driver deltas、partial verification 與清理證據。Unknown outcome 不視為已確定未提交，不重送，也不自動改 CL、deadline 或 retry。

每 case 保存 run/trial IDs、profile/source/binary hashes、完整命令、preflight samples、runtime/schema/CL、pool/socket audit、request counts、driver counters、CQL in-flight、busy/idle workers、E2E RPS 與 p50/p95/p99、CPU、I/O，以及每 node/shard 的 commitlog flush、bytes、cycle、allocation、pending 與 scrape offsets。失敗窗口的 partial RPS 不列作通過效能結果。

雙 shard 和單 shard使用相同的 C、P 時，雙 shard 會讓每 node/cluster data connections 加倍，並增加每 node reactor CPU 數；每 node memory limit 不變，因此每 shard 可用 memory 減少。兩組結果只能比較整體 profile 變化，不能宣稱是單獨 CPU scaling 的因果效果。
