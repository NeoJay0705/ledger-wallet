# 09-02 development design — ledger-txn-sweep 整理

## 結構
```
benchmarks/ledger-txn-sweep/
  Cargo.toml, Cargo.lock, .gitignore      # 自包含 crate；只忽略 /target/ 與 __pycache__（artifacts/ 為已發布證據；本機新 run 也會寫在 artifacts/，提交前須自行檢查 git status）
  src/bin/txn_batch_pg.rs, txn_batch_tidb.rs   # 兩個 client（皆支援 --connections）
  sql/                                    # PG schema 與 statement
  scripts/                                # wrapper、driver、報告產生器與其測試
  artifacts/                              # 已發布的彙整表與各測試點關鍵檔案（sanitized；與來源 artifacts/ 同 layout，工具無需改動即可使用；此目錄入版控，`.gitignore` 不再忽略 /artifacts/）
  README.md
docs/04-xx … 09-xx
```
## 原則
- 程式與測試由來源逐檔複製，只做必要修改（路徑假設、public 清理）；複製後以 `diff` 證明除記錄的修改外一致。
- 已發布資料的 layout 與來源 `artifacts/` 相同，使 driver 的 `audit`、報告產生器、測試無需改邏輯即可在發布資料上執行；發布集合由「產生器與稽核實際開啟的檔案」決定，並以「重現的報告與來源報告 diff 為空（僅允許記錄的 sanitize 差異）」驗證。
- Sanitize：移除家目錄路徑、使用者名稱、主機名稱；掃描規則（`/home/`、使用者名稱、主機名稱、`@`、`token|secret|passw`）對所有新增檔案執行並輸出結果；允許清單僅含已標註的拋棄式本機密碼。
- 彙整表：`scripts/summarize_sweeps.py` 讀已發布 CSV 產生 `artifacts/summary.md`（各系列飽和點、峰值、RPS／延遲／監控摘要）；README 的表格由其輸出貼上，並測試表內數字與 CSV 一致。
## 驗證（為何保留）
Python 全套與 `cargo test`（證明程式在新位置可用）；driver `--dry-run` 與 `audit` 在發布資料上無 VIOLATION（證明資料集完整）；報告重現 diff（證明表格可追溯）；public 掃描（本需求新增風險）；README／docs 連結與引用檔案存在檢查。不重跑 benchmark（成本高且不影響封裝正確性）。
## Tasks
- P1 複製程式與測試、建立 crate、gitignore；Python／cargo 測試與 dry-run 通過。
- P2 發布資料：發布腳本（來源端執行，不入 repo）＋ sanitize ＋ 重現檢查。
- P3 文件：docs 04–08 由來源需求／設計／報告 sanitize 後歸檔，`summarize_sweeps.py`、README、根 README 連結、連結檢查。
- 最後主 agent 獨立做 public 掃描與抽查。

## REVISION（commit 後修正）
結構改為：`Cargo.*`、`src/bin/`、`scripts/`（含測試）、`README.md`（重現步驟）、`RESULTS.md`、`SECURITY-NOTES.txt`、`sweep-imports.example.json`；`artifacts/` 與 `docs/` 為本機輸出且 gitignore。依賴 artifacts 的測試在缺資料時 skip。原「artifacts 發布與重現報告 diff」驗證項目不再適用。
