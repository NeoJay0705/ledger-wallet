日期：2026-10-11。
目標：依 [01-31 ScyllaDB Ledger Wallet 基準測試需求](01-31.raw-requirement-scylladb-wallet-benchmark.md) 評估三節點同步耐久 ledger wallet。
狀態（2026-10-11）：實作與診斷驗證完成。九 case fixed-profile pilot 通過；正式矩陣受 strict capacity gate 阻擋，詳見 [01-33 驗證紀錄](01-33.development-validation-scylladb-wallet-benchmark.md)。

## D08：隔離 crate、固定 server 與耐久設定

實作放在獨立 `benchmarks/scylla-wallet` crate。這避免改動既有 RocksDB 核心與 root `Cargo.toml`／`Cargo.lock`。Rust driver 固定為 1.9.0，版本由 crate 的 `Cargo.lock` 鎖定。

三個 Scylla node 使用 `scylladb/scylla:2026.1.14` 首次 pull 後解析出的完整 digest：

```text
scylladb/scylla@sha256:333b9ab3a3214c7f98af100711c51df7f58964e8227e6d26050e889ebb216df1
```

受測 release tag `scylla-2026.1.14` 對應 commit `0dbea6201d676548993bc5889d8f4a34dd6ef54c`。實際 image 的 `scylla --version` 為 `2026.1.14-0.20260924.0dbea6201d67`，build id 為 `7f91ae5258e0d48ee92f8bc35bd75afe748b4625`。Runner 同時保存 image ID、RepoDigests、labels、tag commit 與每個 node 的完整版本輸出；tag commit 與 build version 不一致時 trial 失敗。

CQL readiness probe 使用 `SELECT JSON release_version FROM system.local`，只確認 CQL 可回應有效且非空的版本欄位。該欄位是 CQL 相容版本（本機回報 `3.0.8`），不是 Scylla binary build version。固定 release 的 binary 對應由獨立的 `scylla --version`、image metadata 與 tag commit evidence 驗證。

Runner 保存固定 release 的 [`db/config.cc`](https://raw.githubusercontent.com/scylladb/scylladb/scylla-2026.1.14/db/config.cc)、[`db/config.hh`](https://raw.githubusercontent.com/scylladb/scylladb/scylla-2026.1.14/db/config.hh)、[`db/commitlog/commitlog.cc`](https://raw.githubusercontent.com/scylladb/scylladb/scylla-2026.1.14/db/commitlog/commitlog.cc)、[`db/commitlog/commitlog.hh`](https://raw.githubusercontent.com/scylladb/scylladb/scylla-2026.1.14/db/commitlog/commitlog.hh) 與 Rust driver 1.9.0 [`scylla/src/network/connection.rs`](https://raw.githubusercontent.com/scylladb/scylla-rust-driver/v1.9.0/scylla/src/network/connection.rs)，記錄 URL、SHA-256 與 tag commit。Source hash 只說明保存的 tag source；image 對應另由 image inspect 與執行中 binary version 核對。原始 source 與 manifest 已保存於 `target/scylla-wallet/runner-validation/source-evidence/`。

所有正式及診斷 trial 固定下列 node 設定：

| 設定 | 固定值 |
| --- | --- |
| RF | 單一 DC，RF=3 |
| `durable_writes` | `true` |
| Wallet write/read consistency | `THREE` |
| `commitlog_sync` | `batch` |
| `commitlog_use_o_dsync` | `false` |
| Commitlog total space | 1024 MiB/node |

`commitlog_sync_batch_window_in_ms` 在固定 release 有註冊，但檢查 `commitlog.cc` 未見讀取該欄位；另保存 `commitlog::config` 及 `batch_cycle` 執行路徑證據。本輪不以註冊欄位推論有實際等待 window，不做 window sweep。此 release 沒有可驗證的獨立逐筆 fsync profile，故標記 `unsupported`，不以 `periodic` 代替，也不宣稱每筆交易各自觸發一次 fsync。

Server 來源行為證據記錄 `do_flush` 呼叫 `_file.flush()` 並增加 flush counter 的路徑。`scylla_commitlog_flush` 是 commitlog flush counter，不是 request 數，也不能直接推論 fsync 次數或每筆 request 的 flush 歸屬。若 syscall trace 因 host `ptrace_scope=1` 被拒絕，記錄不可用，不改變 host 安全設定。

`system_schema` 的 metadata／DDL bootstrap 與 `system.clients` 稽核使用 CL=ONE，並在量測窗外執行。原因是 `system_schema` 使用 local replica；對它要求 THREE 會得到 `Unavailable(required=3, alive=1)`，這不代表三節點叢集不健康。建立 wallet keyspace 後等待 schema agreement。Wallet seed、讀、寫、replay 與 verify 一律維持 CL=THREE，不因 bootstrap 例外降低。

固定 release 的 [ks_prop_defs.cc](https://raw.githubusercontent.com/scylladb/scylladb/scylla-2026.1.14/cql3/statements/ks_prop_defs.cc) 將 `tablets.enabled=false` 解讀為 absent optional value；啟用 tablets 的 NetworkTopologyStrategy 即使初始值為 0，仍是 present value。[schema_tables.cc](https://raw.githubusercontent.com/scylladb/scylladb/scylla-2026.1.14/db/schema_tables.cc) 只在 `initial_tablets` optional 有值時才寫入 `system_schema.scylla_keyspaces`。因此 runner 分別以 CL=ONE 查 `system_schema.keyspaces` 的 `durable_writes, replication`，以及 `system_schema.scylla_keyspaces` 的 `initial_tablets`。後者查詢必須成功；0 rows 或單一 null row 才視為 tablets disabled，任何數值（包含 0）、非 null 值、多 row 或查詢／schema 錯誤都使 trial 失敗。`keyspace-validation.json` 保存兩條 query、raw output、解讀、source URL、tag commit 與 source SHA-256。

實機啟動證據顯示 `developer-mode=0`、`io-setup=0` 在本機容器磁碟缺少 I/O scheduler properties 時 restart-loop。固定本機測試 profile 因此採 `developer-mode=1`、`io-setup=0`、`overprovisioned=1`，並在每個 trial 驗證生效設定。此 profile 未執行 device autotune，且三個 node 共用 host/device；結果只代表本機成本，不代表 production tuning。初始失敗 log 保留於 `target/scylla-wallet/runs/core-smoke-20261011T102743Z-afbc3b71/logs/nodea-devmode0-failed.log`。

固定本機 AIO profile 對所有 S/C case 傳入 `--reactor-backend linux-aio`、`--max-networking-io-control-blocks 1024` 與 `--reserve-io-control-blocks 1024`，不修改 host sysctl 或安全設定。Scylla release 的 `main.cc:716` 預設 networking IOCB 為 50,000；固定 Seastar submodule `bf882627c3f813c8cfb88cb595ceed34d6462300` 的 `reactor.cc` 會依剩餘 host budget 動態調低 network IOCB。這裡固定為較小的本機 benchmark budget，只代表本輪 C≤48 的受限 in-flight profile，不代表 production-optimal 設定。Runner 保存 `main.cc`、`src/core/reactor.cc`、`include/seastar/core/reactor.hh` URL、SHA-256 與 submodule commit。

Scylla 每個 node 的 process memory 設定為 8 GiB。Docker `HostConfig.Memory=10 GiB` 且 `HostConfig.MemorySwap=10 GiB`；兩者相同表示 10 GiB cgroup memory limit 外沒有額外 swap allowance。Node 不設 CPU quota。Node 使用明確 cluster name、seed list、listen/broadcast RPC 設定、隔離 Docker bridge 與固定 bridge IP；不 publish host ports。正式設定由 Rust crate 建立 RF3 keyspace，並停用 tablets。若固定 release 不接受 tablets-disabled schema，停止該 trial，不靜默改用 tablets。

## D09：固定 Independent 寫入與 worker／connection 對應

每筆 logical transaction 固定兩個同 partition statements，使用單 partition `UNLOGGED BATCH`，不跨 partition 組批，也不增加收集等待。每筆估算 encoded request bytes 小於 1 KiB；實際固定 batch byte cap、statement 數與報告值由 crate 保存。

每個 account 有固定 owner 排程及 frozen flag。每個 account 的 read-modify-write、replay 與 reply 依序完成。不同 account 可並行。全域 admission queue 上限為 50,000；C 個 DB worker 各最多等待一個 workload CQL operation。全部 worker 共用一個 Scylla Session。`C` 是 DB worker 數，也是目標資料連線總數，不是 Tokio thread 數；driver 可在同一實體連線 multiplex requests，worker 不獨占連線。

每 node 有 S 個 Scylla shards 時，PerShard pool 設定 `P=C/(3*S)`，要求整數且大於零。資料連線目標須以 `system.clients` 內對應 `SESSION_ID` 的 `client_options` 稽核實測，不能以 PerShard 設定值替代證據。僅將帶 `DRIVER_CONFIG` option 的控制連線分類為 control；不盲目每 node 扣除一條 connection。控制、metadata、監控及重連連線另行記錄。

| Scylla shards/node S | DB workers／總資料連線 C=12，P | C=24，P | C=48，P |
| ---: | ---: | ---: | ---: |
| 1 | 4 | 8 | 16 |
| 2 | 2 | 4 | 8 |
| 4 | 1 | 2 | 4 |

Tokio runtime 固定 4 threads，服務、負載產生器及 Python monitor 共用 CPU 6,7,14,15。C=12/24/48 是聯合 worker／connection scaling；不能稱為純 coroutine 收益。

| S | Node A cpuset | Node B cpuset | Node C cpuset | Service/load/monitor pool |
| ---: | --- | --- | --- | --- |
| 1 | 0 | 2 | 4 | 6,7,14,15 |
| 2 | 0,1 | 2,3 | 4,5 | 6,7,14,15 |
| 4 | 0,1,8,9 | 2,3,10,11 | 4,5,12,13 | 6,7,14,15 |

S4 使用每 node 兩個 physical cores 的四個 SMT threads，並非四個獨立 physical cores。啟動後讀取 Scylla 每個 OS task 的實際 affinity；S1 主 Scylla TID 視為 reactor 0，其餘 shard 以 reactor thread 名稱辨識。必須核對每個 reactor 為單 CPU mask 且 CPU 集合吻合預期。OS、IRQ 與其他程序仍可能干擾。

## D10：Wallet schema 與請求編碼

Wallet table 以 `account_id bigint` 作 partition key，clustering key 為 `(kind tinyint, tx_id bigint, transaction_at bigint)`。`kind=0, tx_id=0, transaction_at=0` 是 account static state sentinel；`kind=1` 是 ledger row。

Static state 欄位為 `balance blob`（8-byte big-endian u64）、`version bigint`、`write_clock bigint`。Ledger 欄位為 `op tinyint`、`amount blob`、`outcome tinyint`、`balance_after blob`、`ledger_version bigint`、`ledger_write_clock bigint`。所有 CQL key 值須能表示為非負 `i64`；balance 保留完整 `u64` 範圍。

每個新 request（包括業務拒絕結果）配置下一個 version。Write clock 使用 checked 算式 `max(now_micros, old_clock + 1)`；overflow 使 trial 失敗。`transaction_at` 是 producer 提供的 request key，與 write clock 分開編碼；它不設定 Scylla write timestamp。

## D11：Replay、unknown commit 與單 writer

Owner 下依序執行兩個 SELECT，分別讀 current static state 與該 key 的 ledger。兩個 SELECT 不構成同一 snapshot。相同 key、不同 body 回傳 conflict，不作新 mutation。相同 body 以新 write clock 重寫「目前」static balance/version，並使用 ledger 原 write clock 重寫該筆 immutable ledger；兩筆寫入放在同 partition batch，以 CL=THREE 建立耐久確認。

Replay 不可用舊交易的 balance 覆蓋較新的 current balance，也不可僅 SELECT 到 ledger 就回覆成功。任何 write 產生 unknown 結果時，freeze account 並使 trial 失敗；不 retry、不降低 consistency，也不把查無 ledger 解讀成未提交。未解 unknown 維持 fail-closed。

Credit overflow、insufficient funds、invalid amount 是可 replay 的已保存拒絕結果。Conflict 不新增 mutation。此服務只有本機 owner；沒有跨程序 writer fencing。禁止 writer 重疊。程序 crash 後須先確認舊 writer 與其 requests 結束，再由新 writer 接手。

## D12：Cancellation、shutdown 與錯誤

成功執行 worker channel `try_send(job)` 是 request acceptance 的線性化點；只取得 admission permit 不代表 request 已接受。Accepted job 由 worker 保有 account guard 與 permit；caller 取消不會取消已接受的資料庫 I/O。Worker 先送出 reply，再釋放 guard 與 permit。Reply 遺失不表示交易未提交。

Shutdown 關閉 admission 與所有 sender，drain 已接受工作，deadline 為 120 秒。超時結果標 unknown，abort 並 await workers；先確認程序停止，再清理資料。Read/decode 錯誤使 trial 失敗；write 的任何不確定錯誤轉成 `CommitOutcomeUnknown`。任一 node unavailable 時，THREE 不會有成功 ack。錯誤、validation 與 cleanup 狀態分欄保存。

## D13：計時窗、負載與統計

Seed 在量測窗外建立 50,000 個帳戶，每個初始 balance=100。正式負載為 50,000 users，每人順序送出 200 requests，Credit/Debit amount=1 交替；每帳戶最後 balance=100。每個 trial 共 10,000,000 logical requests。

所有 client 到 barrier 後，CLI 發出 `ready_to_measure`，等待 runner 建立 start gate。Gate 只作為開始前置條件，不是時間窗 timestamp。Gate 開啟後，CLI 先取 process/counter 起點，記錄 `Instant` 起點，再立即 flush `measuring` event，最後 release 共用 client start barrier。量測從該 `Instant` 至最後一個 caller reply。Latency 從 submit 前到 reply。Join、drain、verify 不計入時間窗。CLI 以 `measurement_start_unix_ns`、`measurement_end_unix_ns`、`window_end_offset_ns` 保存時間窗；不使用 event flush time 代替開始點。

正式矩陣使用 S={1,2,4}、C={12,24,48}，每組三輪，共 27 個 trials。每輪 deterministic rotate 九種 case；不得挑最好 trial。每個 trial 驗證每個帳戶完整 200 筆 ledger 的 key/body/outcome 與 balance/version，不把一千萬筆 ledger 全放進記憶體。Latency 使用 HDR histogram，三位有效精度；每 64 個 global request 保留一筆原始 sample。先逐 trial 計算分位數，再對同一 case 的 trial p50/p95/p99 等作 median/min/max；不可將多輪資料合併後算分位數，也不可將 stage p99 相加。

Smoke 使用 100 users × 20 requests；pilot 使用 1,000 × 20。兩者存入獨立 run directory，明確標記 diagnostic/custom workload，不混入正式統計。僅當完整 27 trial 的負載、metrics、連線稽核與 cleanup 都通過，runner 才標 `formal_complete=true`。任何 subset、較小 workload 或缺 case 均為 `formal_partial` 或 diagnostic。

舊 matrix `run-20261011T113617Z-7ccebf47` 是歷史 diagnostic：S1/S2 六個 trial pass 且 cleanup clean，S4 三個 trial 因 nodeC startup 要求的 minimum AIO 266,252 高於當時 host `aio-max-nr=262,144` 而失敗且 cleanup clean。因舊 S2 實際 networking IOCB 已動態降至 27,482，舊六個 pass 不與新 profile 合併。後續固定 1024 IOCB profile 的九個初始 case 已在新的 `run-20261011T145542Z-8bf4d8f3` 全部通過；該 run 每 case 一次，維持 diagnostic 標記。

## D14：監控、連線稽核與前置條件

量測期間每秒對每 node 保存完整 raw Prometheus gzip；同時保存 host proc/stat、Scylla 真正 host PID 的 proc stat/status/io、cgroup v2 `io.stat` fallback、host network、實際唯一 backing device counters、Python monitor CPU 與 CLI process CPU。三個 node 共用同一 device 時只計一次，不將同一 device counter 乘三。Scylla PID 由 `docker top <container> -eo pid,args` 解析；只接受 command 第一個 executable token 的 basename 恰為 `scylla` 的 row，排除 housekeeping 與 exporter。必須恰有一個符合項目；不能將 Docker init PID 誤當 Scylla。

每個 Prometheus scrape 保留 timestamp、整份 raw text 與 metric-name evidence。必要 metrics 分組包含 reactor CPU、write/request latency、cache、flush、compaction、commitlog flush、backlog、errors、timeouts 與 network。若 pinned release 沒有某個 metric，報告 N/A 或明確等價 counter；不編造 metric。缺必要 metric、process CPU/RSS/I/O、commitlog window delta 或連線證據時，trial 不具正式資格。

固定 release 的 `service/storage_proxy.cc` 對 coordinator read/write timeout 與 error metric family 使用 `set_skip_when_empty()`。為了讓 server 在確實沒有事件時輸出真實零值，每個 trial 生成 `metrics-relabel.yaml`，以唯讀 bind mount 掛入 node，並使用 `--relabel-config-file` 載入。設定只將 `.*reactor_utilization` 標記為 `basic`，並對 `.*storage_proxy_coordinator_(read_timeouts|write_timeouts|write_errors.*|read_errors.*)` 套用 `report_when_empty`；`metric_family_configs` 保持空清單，不 drop 或 aggregate 指標。`metrics-relabel-profile.json` 保存 YAML SHA-256、規則、來源 URL/hash 與固定 Seastar submodule commit `bf882627c3f813c8cfb88cb595ceed34d6462300`；launch evidence 核對 node command flag、唯讀 mount 與檔案 hash。這只讓 server 為空的計數器 family 輸出 0；量測窗內仍未觀察到 required metric 時，報告 N/A 並使 trial 不具正式資格。

`scylla_commitlog_flush` 是固定 release 實際存在的 flush counter。Runner 保存每 node/shard `flush`、`bytes_written`、`cycle`、`alloc` 的起止值、window delta 與 sampling offset。Counter reset、缺 sample 或缺 shard 時記為 invalid，不能填 0。報告同時列 logical requests/replies、預期 partition mutations=1/request、application CQL operations=3/request（2 reads + 1 batch），讓人比較 C 與 group commit。這些 flush delta 不等同 request count，不從 DB write await 推論 fsync duration。

`ready_to_measure` 前 runner 用 session id 查詢每個 node `system.clients`，把 DRIVER_CONFIG 控制連線與 data connections 分類。只有 data connections 總數恰等於 C、每 node 恰等於 C/3、P=C/(3S) 時才放行 start gate。Measured window 內以 CLI PID 的 TCP socket inode／tuple 每秒快照辨識 connection 變動；完成 `verified` 後、finish gate 前再做 `system.clients` audit。此 snapshot 可漏掉比取樣週期更短的瞬時重連，限制需保留在 report。

Formal 開始前，runner 連續三次取樣確認 host CPU busy ≤10%、實際 output/run directory 所在單一 backing device busy ≤5%、available disk ≥32 GiB 且不小於容量估算、available memory ≥32 GiB。最多等待 60 秒。容量估算含 RF3 data、compaction、每 node commitlog 與 16 GiB reserve。2026-10-11 的 formal attempt 在建立 cluster 前被 strict preflight 阻擋：`sdb2` 可用 41,649,401,856 bytes，低於 82,042,421,248 bytes 的估算。此 attempt 僅取樣一次，沒有三次連續通過。不得為了執行而下調估算。Preflight 必須檢查 `--output-root` 所在檔案系統，不可檢查 repo 另一個 filesystem。

啟動後不得以 Scylla reactor busy loop 為由套用 idle-CPU 背景閘。記錄 SMT sibling map 與 OS interference；啟動後只檢查背景及磁碟狀態。Smoke/pilot 可使用明確 relaxed preflight，但不改正式資格。

每個 trial 在建立 network/container 前讀取 `/proc/sys/fs/aio-max-nr` 與 `/proc/sys/fs/aio-nr`，要求可用 headroom `aio-max-nr - aio-nr >= 3*S*(max_networking_io_control_blocks_per_shard=1024 + storage_io_control_blocks_per_shard=1024 + preempt_io_control_blocks_per_shard=2) + max(fixed_headroom=1024, reserve_io_control_blocks_per_node=1024)`。每 node 的 `--reserve-io-control-blocks=1024` 另行保存，不當作 per-shard storage 再乘 S；最終全域可用 headroom 至少保留一個 process reserve，不將 reserve 乘上 S 或 node 數。未知或不足即寫入失敗的 `aio-budget.json` 並停止，不建立 Scylla resources。Run host inventory、run config、dry-run 與 trial budget 都保存原始兩個值、分項需求、profile 與結果；host counters 無法讀取時不能假定有餘裕。

啟動證據 gate 要求 tablets query 輸出明確證明零筆資料，或明確的一筆 null JSON row；空白輸出無效。建立 workload 前，runner 保存 Docker log streams 與 hashes，並驗證所有 node 使用 Linux AIO 且沒有 IOCB autoreduction。與該條件無關的 `io_uring` 到 `epoll` warning 可接受。Final startup-evidence validators 已對 fixed-AIO pilot 九個原始 case outputs replay 通過；此 replay 不重跑 workload，也不修改原 run source hashes 或 raw artifacts。Runner 的 validation source hashes 以獨立 replay record 保存。

## D15：資源所有權、清理與結論邊界

每 trial 建立新 cluster、唯一 nonce、Docker labels、所有權 marker 及 manifest。Data bind mounts 僅位於 `target/scylla-wallet/runs/<run_id>/trials/<trial_id>/owned-data/{nodea,nodeb,nodec}`。Logs、Prometheus、CSV、result、runtime config、source hashes 與其他報告放在 owned-data 之外。

Runner 只操作 labels/nonce 與 mount 都吻合的容器、該 trial 的 network 及該 marker 下的 data。它以 `docker network ls -q` 找到候選 ID，再用 `docker network inspect` 取得 canonical full `Id`；用 inspect ID 核對 ownership manifest，避免把短 ID 當成完整 network ID。使用 `docker create` 後先保存 container id 與 ownership manifest，再 `docker start`，讓部分啟動也可稽核。停止前先 inspect 並核對 labels；停止後再次 inspect 確認 stopped。清理順序為 client drain/verify、stop 已核對的容器、確認 stopped、移除 owned containers、確認無容器仍使用 owned mounts、移除 owned network，最後只清除標記下 node data。Root-owned bind mount data 用 pinned image helper 精確清理。清理後保留 log、raw Prometheus、CSV、config、version、source hash 與 cleanup audit。

若 inventory/inspect 不能證明 labels、mount、network 或 stopped 狀態，保留資料並報 cleanup error；不使用 `docker prune`，不以任意 `sudo rm` 刪除 foreign path。失敗也執行 safe cleanup。Formal 27 cases 全部通過才可稱完整性能報告。有限 closed-loop workload 不證明 steady-state capacity、hot-account 行為或長期 partition growth。

Trial 收到 SIGINT 時，runner 會記錄 `interrupted`，終止 CLI 並執行 finally cleanup。Cleanup 完成後停止其餘 matrix cases、寫出 run report，並以 nonzero exit 結束。若 ownership 證據不足，cleanup 仍保留 owned-data 並報錯。

## 執行流程

```text
Python main -> resolve parameters -> run_trial
  -> OwnedCluster.start -> docker create -> persist ownership manifest -> docker start
  -> verify version/config/schema/affinity -> start CLI process
CLI main -> parse_args -> EventLog -> ScyllaStore::connect -> ready pool
  -> seed_account (CL=THREE) -> Service::start -> run_clients
  -> ready_to_measure -> runner verifies pool + system.clients -> start gate
  -> clients reach start barrier -> record Instant -> flush measuring -> release barrier
  -> Service::submit -> admission permit -> account owner -> worker_loop (C workers)
       -> process_job -> WalletStore::load (two sequential SELECTs) -> compute
       -> WalletStore::commit -> shared Session .batch (UNLOGGED)
       -> Node A/B/C: commitlog batch -> fsync acknowledgement path -> replica reply
       -> THREE reply -> worker sends caller reply -> release account owner
  -> client_end -> CLI disables metrics -> Service::shutdown -> verify_all
  -> verified -> awaiting_runner_audit (Session remains open)
  -> runner stops monitor -> system.clients post-window audit -> finish gate
  -> CLI rechecks same session -> result.json -> exits
  -> runner inspects/stops owned nodes -> removes owned resources/data -> cleanup.json
```

Replay 路徑：

```text
process_job -> read current static + ledger
  -> same key / different body: conflict, no mutation
  -> same body: current static + original ledger durable batch at THREE
  -> successful durable acknowledgement
unknown write -> freeze account -> fail closed -> invalidate trial
```

這裡的 `fsync path` 表示固定 batch commitlog acknowledgement path；不表示 syscall trace 已觀察到每一個 request 各自呼叫 fsync。`system_schema` bootstrap 與 `system.clients` audit 的 CL=ONE 是計時窗外的系統 metadata 操作；上面的 wallet mutation 與 user data reads 保持 THREE。
