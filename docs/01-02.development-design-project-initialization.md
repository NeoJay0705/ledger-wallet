# 專案初始化設計

對應需求：[01-01.raw-requirement-ledger-wallet.md](01-01.raw-requirement-ledger-wallet.md)。本文件只定義開始實作前的 Rust 專案骨架；交易、帳戶、持久化與復原功能另由後續設計處理。

## 目標與假設

- 建立可由其他開發者取得、閱讀及編譯的最小 Rust 專案；本階段不提供帳本功能或對外服務。
- 採用使用者已確認的 Rust 1.98.1。Rust 官方目前沒有正式 LTS 發行版，因此以固定工具鏈版本取得可重現的開發環境；更新版本需明確修改設定。
- 原始需求中的 `(account_id, tx_id)` 唯一性、WAL、LSM 與 Projection DB 是未來功能設計的依據，不在初始化階段選定套件或建立空模組。

## 專案結構與責任

| 路徑 | 責任 |
| --- | --- |
| `Cargo.toml` | 單一 `ledger-wallet` binary package，edition 2024，`rust-version = "1.98.1"`；目前沒有第三方依賴。 |
| `Cargo.lock` | 固定應用程式依賴解析結果，納入版本控制。 |
| `rust-toolchain.toml` | 將本專案工具鏈固定為 1.98.1。 |
| `src/main.rs` | 空的程式入口；目前不讀寫資料、不開啟服務。 |
| `.gitignore` | 排除 Cargo 的 `/target/`，保留既有忽略規則。 |
| `README.md` | 說明專案狀態、工具鏈、最小開發指令及需求文件入口。 |
| `docs/` | 保存原始需求與依編號遞增的設計文件。 |

本階段維持單一 package；沒有足夠的功能邊界可支持預先拆分 crate 或 workspace。後續若需要模組，應由對應功能設計定義責任與介面。

## 資料模型、流程與介面

初始化階段沒有帳本資料模型、交易資料流、公開 API 或持久化格式。`main` 正常結束且沒有輸出。不得將空入口視為已滿足原始需求中的交易或復原行為。

## 實作與驗收

1. 保留現有 Cargo package、lockfile、工具鏈設定、空入口與 `.gitignore` 規則；不加入依賴或功能佔位程式碼。
2. 新增簡短 `README.md`，讓新貢獻者知道目前狀態，以及需求與設計文件所在位置。
3. 使用固定工具鏈執行 `cargo fmt --check` 和 `cargo check --locked`，確認格式及骨架可編譯。此階段沒有值得建立的功能測試。

## 錯誤處理、取捨與後續擴充

目前沒有執行期操作，因此沒有應用程式錯誤類型。工具鏈未安裝、lockfile 不一致或編譯失敗時，由 rustup/Cargo 的診斷訊息指出問題。固定版本可重現，但需要後續主動升級；單一 binary package 降低初期維護成本，但不預設未來的模組架構。交易語義、錯誤契約、儲存技術與測試案例應在功能設計中依原始需求另行決定。
