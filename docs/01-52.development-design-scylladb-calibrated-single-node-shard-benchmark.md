# ScyllaDB Wallet 校準後單節點 shard 擴展：設計

日期：2026-10-12。

目標：實作 [01-51 原始需求](01-51.raw-requirement-scylladb-calibrated-single-node-shard-benchmark.md)。

需求編號：01。文件序號：52。
狀態：設計已定；Runner 與 CLI 支援尚待驗證。

此設計沿用 [01-48 RF3/CL3 profile](01-48.raw-requirement-scylladb-memory-lwt-rf3-s2-concurrency-benchmark.md) 與 [01-49 shard/pool 設計](01-49.development-design-scylladb-memory-lwt-rf3-s2-concurrency-benchmark.md)。本次只增加校準與單節點執行 profile。Wallet CQL、memory cache、owner lock、LWT、timeouts 和 fail-closed 行為不變。

單節點執行需要 Runner 能依 inventory 支援 1 或 3 個 distinct、non-empty endpoints。Runner 必須讓 node count 驅動所有 node 數量 assertions、audits、cleanup、monitor、AIO 和 disk sizing。既有三節點 default formal contract 保持不變。

CLI 與 Store 也必須接受 1 或 3 個 distinct、non-empty endpoints。RF 不得大於實際 node 數。Default RF/CL 保持 RF=3、read/write CL `THREE`；不得靜默改 default。單節點命令必須顯式使用 RF=1、read CL `ONE`、write CL `ONE`。Legacy `connect` 與 `connect_with_pool` API 保留 RF3 defaults；單節點只可透過明確 profile API 使用 RF1。Store 直接 API 呼叫也必須拒絕 2 個節點、重複 endpoint、RF 高於 node count、錯誤 consistency 和 overflow configuration。

Pool target 與 worker 數分開。對 N 個 node、S shards 和每 node/per-shard P connections，總 data connection target 為 `D=N×S×P`。當 P 明確指定時，C 不必能被 `N×S` 整除。Legacy worker-derived pool 仍依 `C/(N×S)` 計算，並拒絕不能整除的值。

`wait_for_pool_ready` 必須接收 expected node count。每次等待時都核對 driver 發現的 node 數完全相同、所有 nodes 已連線、datacenter 一致，並且 data connections 恰為 D。不得只在第一次檢查 node 數。不得接受意外發現的 peer。

## Calibration 流程

1. 以 inventory 核對 `/dev/sdb2`、ext4、mount point 和目前可用空間。
2. 在該 filesystem 建立新的 owned temporary directory。保存目錄、mount、device、filesystem、開始空間和擁有權證據。
3. 以固定工具與 pinned input 執行 calibration。預期時間 180 秒，外部上限 600 秒，temporary data 上限 32 GiB，剩餘空間至少 64 GiB。
4. 保存四個 tool-defined raw capability values、各自 `floor(raw × 0.75)` node budgets、tool/image digest、輸入與輸出 hashes、exit status 和 provenance。
5. 以唯讀 properties 注入 runtime，設定 Scylla/Seastar I/O scheduler 的 node budget。Runtime gate 必須確認載入的設定，並比對 properties hash、來源與 provenance。S=1 與 S=2 使用同一份 node budgets。
6. 若工具不支援 ext4、ext4 拒絕、device 不符、輸出不完整、時間或空間 gate 失敗，立即停止。不格式化，不換 filesystem，不重跑以取得較高數字。

四個 raw capability values 供 Scylla/Seastar I/O scheduler 設定 node budget；runtime gate 驗證實際載入的設定。此 budget 不是 cgroup 或 kernel I/O 硬隔離，也不預測單次 fsync latency。

Pinned `iotune` 不提供 file-size 上限。工具可能先 unlink 測試檔，再建立邏輯大小很大的 sparse 檔。因此 32 GiB gate 計算實際配置的 blocks，不看 sparse logical length，也不能用已 unlink 的目錄或 `du` 判斷。若 ext4 接受 calibration，外部 watchdog 每 0.5 秒或更快讀取容器 `/proc/<iotune_pid>/fd`。以 `(device, inode)` 去重，將 evaluation device 上測試檔的 `st_blocks × 512` 加總。配置量達 24 GiB 時停止工具。若剩餘空間低於 64 GiB，或監測資料無法讀取，也立即停止。超過 32 GiB、watchdog 失效或外部 10 分鐘期限到達，該 calibration invalid。不得修改工具或 host filesystem 來繞過限制。

## 執行矩陣

| 階段 | Node | RF / wallet CL | S | C | P | D | Workload | CPU |
|---|---:|---|---:|---:|---:|---:|---|---|
| Smoke | 1 | 1 / ONE | 1 | 128 | 3 | 3 | 32 × 1,000 | node `0` |
| Full case 1 | 1 | 1 / ONE | 1 | 128 | 3 | 3 | 1,024 × 1,000 | node `0` |
| Full case 2 | 1 | 1 / ONE | 2 | 128 | 3 | 6 | 1,024 × 1,000 | node `0,1` |

每個 case 的 Service、load clients 和 internal monitor 使用 CPU `6,7,14,15`。每個 Scylla node 配置 8 GiB memory，cgroup limit 為 10 GiB。每個 full case 使用一個 fresh owned node data directory，repeats 為 1。

Scylla image 沿用 [01-48](01-48.raw-requirement-scylladb-memory-lwt-rf3-s2-concurrency-benchmark.md) 與 [01-49](01-49.development-design-scylladb-memory-lwt-rf3-s2-concurrency-benchmark.md) 的 pinned image。單節點支援完成後，以本次 Rust source 建立新的 release binary；保存 compiled-source manifest 與 binary SHA，不沿用舊 binary SHA。Wallet 交易邏輯不變。單節點 keyspace 使用 RF1、`durable_writes=true`。Wallet read/write CL 是 `ONE`，LWT serial CL 是 `LOCAL_SERIAL`。Metadata DDL 仍使用適合 bootstrap 的 CL1。

保留 dev mode 1、`io_setup=0`、overprovisioned 1、batch commitlog、原有 fsync acknowledgement、timeout 和 no-retry。每個 measured accepted request 仍只使用一個 memory-LWT profile 的 `INSERT ... IF NOT EXISTS`。Measurement 中 measured SELECT 是 0。不得更改 Rust transaction path。

## Runner 與 CLI 範圍

Runner 增加 N=1 的明確 profile，同時保留三節點既有 default。所有 node 數相關操作讀取 inventory node count，不寫死為 3。Runner 的 calibrator output 必須保持原始格式與 hash。只讀注入值必須帶來源、calibration hash 和 runtime validation 結果。

Rust CLI/Store 的必要相容範圍僅限 endpoint 數和 connection target：

- Parse 和 Store API 接受 N=1 或 N=3；其他值拒絕。Endpoints 必須 distinct 且 non-empty。
- RF 必須介於 1 和 N。read/write CL 不得高於 RF。RF 和 CL defaults 不變。
- 單節點需顯式設定 RF1/CL1。Legacy RF3 connect wrappers 在單節點拒絕設定，不自行降級。
- D 依 `N×S×P` 計算。pool readiness 每次都驗證 node discovery、連線狀態、datacenter 和 D。
- Wallet schema、seed、preload、LWT、cache、owners、verification 與 failure semantics 不變。

Calibration 注入的 custom `io-properties-file` 是新的 local calibrated pilot profile，不是舊三節點 formal profile。Runner 必須拒絕同時指定 `mode=formal` 與 custom I/O properties file。沒有 custom file 的舊三節點 formal contract 保持不變。

## Gate、保存與停止

Runner 依序執行 calibration、smoke、S1 full case 和 S2 full case。Smoke 使用 32 個 accounts、32,000 requests 和 32,000 筆 ledger rows，讓 1 Hz required metrics 有足夠時間至少取得一筆 window sample。Full case 驗證 1,024 個 accounts、1,024,000 requests 和相同數量的 ledger rows。每個階段都要檢查 source/binary/configuration hashes、required metrics、driver counters、pool target、runtime profile、完整 correctness 和 owned cleanup。階段失敗時停止，不開始下一階段。不自動 retry、不放寬 CL、不延長 timeout。

Full case success 需要 1,024,000 requests 全部 accepted、applied、replied，measured SELECT 為 0，driver query delta 等於 accepted，errors/retries/timeouts/unknown outcomes 為 0，1,024 accounts 與 1,024,000 ledger rows 全量驗證，且 owned resources clean。Smoke 使用 32 個 accounts 和 32,000 requests，依實際 workload 全量驗證，並至少取得一筆 1 Hz window sample。Cleanup 只可移除本 run 擁有的 data；ownership 不明時保留資料和 evidence。

保存 calibration raw output、properties、hash/provenance、runtime gate、per-case configuration/source/binary hashes、events、result、RPS、latency、stage metrics、CPU、process/device I/O、node/shard commitlog counters、verification 和 cleanup evidence。RPS 表示單節點總吞吐。

```text
Deployment flow
  calibration on an owned /dev/sdb2 ext4 temporary directory
  -> apply and verify the Scylla/Seastar I/O scheduler profile
  -> create one owned Scylla node and keyspace
  -> run the 32-account, 32,000-request smoke
  -> run the S=1 full case
  -> run the S=2 full case
  -> inspect ownership and clean each case's node data
  -> save evidence; advance only when all gates pass
```

```text
Wallet request flow
  Credit / Debit input
  -> Service::submit
  -> account owner lock
  -> worker_loop / process_job
  -> read cached AccountState and compute
  -> one conditional INSERT ... IF NOT EXISTS LWT
  -> fsync acknowledgement at write CL ONE
  -> publish cache after Applied acknowledgement
  -> reply
  -> drain and verify cache, static state and full ledger

unknown commit outcome
  -> freeze account and fail closed globally
  -> preserve partial results and verify observable state
  -> clean owned data after collecting evidence
  -> stop later stages; do not retry
```
