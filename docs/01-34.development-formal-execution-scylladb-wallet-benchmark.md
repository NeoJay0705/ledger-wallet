## 執行路徑與完成條件

```text
detached supervisor -> runner -> strict preflight
  -> 27 rotated S/C trials (50,000 users × 200 requests each)
  -> Credit / Debit -> Service::submit -> bounded admission
  -> account owner -> worker_loop / process_job
  -> load (2 SELECTs) -> compute
  -> commit (1 same-partition, 2-statement UNLOGGED BATCH)
  -> three replicas commitlog fsync acknowledgement at CL=THREE
  -> reply -> verify -> stop / inspect / cleanup owned resources
  -> run reports -> supervisor result and exit code
```

此 job 已結束。實際 exit code 記錄在 job `result.json`；`run-result.json` 記錄 `formal_complete` 與有效 trial 數；report 與 CSV summaries 也已產生。判斷正式結果時應讀取這些終態檔案，不以較早的 progress snapshot 取代。

Formal pass 必須有完整 27 個有效 trials、必要 metrics、正確性驗證與 clean cleanup。若任何 case invalid 或缺少必要 evidence，結果不能標示 `formal_complete`。

## 限制與解讀

三個 Scylla nodes 共用同一 host 與 device，不是三個獨立故障域。`S=4` 每 node 使用兩個 physical cores 及 SMT siblings；結果不能單獨歸因於 engine。Commitlog group commit 不代表每個 request 各自觸發一次 fsync。沒有已驗證的獨立 per-write fsync profile；沒有使用 periodic 取代。Host policy 不允許 per-request `strace`，process crash 也不等於 power loss。Supervisor 的短暫 affinity transition 需作為背景 interference 保留。本次 job 未取得 27 個有效 cases，不能作成 formal 性能結論；先前 pilot 不能替代 formal 結果。

完整 `target/scylla-wallet` raw artifacts 保存在外部 evidence archive；小型原始檔、derived summaries 與 archive member 索引見 [Scylla evidence package](../benches/data/scylla_wallet/README.md)。01-33 保留原先 capacity-blocked attempt 與 diagnostic 結果；本文件記錄後續 formal job 的執行狀態。

## 歷史單次接續監督 checkpoint（2026-10-12 01:14）

另啟動一個單次 watcher，等待上述 10M-request 診斷結果。它不會先啟動另一個 Scylla job。Watcher 使用 3 秒輪詢、30 秒持久 heartbeat，最多等待 24 小時，並以 `O_EXCL` 加 `flock` 限制只啟動一次。

只有當診斷 trial 完整通過、必要 metrics 齊全、errors/retries/timeouts 均為零、driver query delta 正好 30,000,000、50,000 accounts 與 10,000,000 ledger rows 全量驗證通過、cleanup clean、source/binary hashes 相符，且三個 containers 與該 run network 確認不存在時，watcher 才會啟動新的預設 27-case formal job。新 job 會重新執行自己的 strict preflight。任何條件不符，watcher 會拒絕啟動並結束，不改 deadline，也不重試。正式矩陣任一 trial 失敗時，runner 會在 cleanup 後停止。

診斷使用 `--mode formal`，但單 case workload 仍是 custom workload。依 runner contract，即使該 trial 本身通過，少於 27 個 cases 的 run 仍會以 `formal_partial` 結束，exit code 1。Watcher 必須依 trial 的完整證據判定是否符合啟動條件，不能只把這個 exit code 當作 storage failure，也不能把單 case 診斷稱為 formal pass。

Watcher 的診斷驗證與 Docker absence check 均通過後，啟動預設 27-case formal run。Run `run-20261011T173702Z-c88fb8e8`，job `formal-conditional-20261011T173701Z-99b604d1`，於 2026-10-12 05:05:07.469699 UTC（13:05:07 台北時間）結束。共嘗試 23/27 trials：22 passed、1 failed、4 未執行。Job exit code 1，`formal_status=formal_partial`、`formal_complete=false`。原 run 永久保留為 partial。

22 個 passed trials 各完成 10,000,000 requests，合計 220,000,000 個已回覆、已套用並通過完整 account/ledger verification 的交易，以及 660,000,000 個應用層 CQL operations。這 22 個通過的 trials 中，errors、retries、timeouts 都為零。23 個已執行 trials 均通過 required-metrics validation 並完成 clean cleanup；trial 023 的 correctness failure 仍使整個 run invalid。
