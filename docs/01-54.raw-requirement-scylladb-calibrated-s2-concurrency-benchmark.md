日期：2026-10-13。

目標：在既有單節點校準 profile 上增加 Wallet 併發，觀察應用、Scylla、commitlog 與主機裝置 counters。

需求編號：01。文件序號：54。

狀態：已授權；實測尚未開始。

本需求延續 [01-51 原始需求](01-51.raw-requirement-scylladb-calibrated-single-node-shard-benchmark.md)、[01-52 設計](01-52.development-design-scylladb-calibrated-single-node-shard-benchmark.md) 和 [01-53 單節點 S1/S2 結果](01-53.development-analysis-scylladb-calibrated-single-node-shard-benchmark.md)。本次只測 S=2 的併發擴展，不重新校準，不增加 smoke，也不重跑 C=128 baseline。

## 固定執行 profile

| 項目 | 固定值 |
|---|---|
| Scylla nodes | N=1 |
| Replication / durability | RF=1；`durable_writes=true` |
| Wallet read/write consistency | `ONE` / `ONE` |
| LWT serial consistency | `LOCAL_SERIAL` |
| Shards | S=2 |
| DB workers / in-flight limit | C=256；worker 與 C 為 1:1 |
| Driver pool | P=3 per shard；S=2 時 D=6，C 增加時仍固定 |
| Routing | round-robin |
| Workload | 1,024 users × 1,000 sequential requests；每個 user 收到 reply 後再送下一筆；總數 1,024,000 |
| Operations | amount 1；512,000 Credit 與 512,000 Debit 交替 |
| Repeats | 每個 case 一次；只在通過 continuation gate 後測 C=512 |
| Scylla CPU | `0,1` |
| Service、load、monitor CPU | `6,7,14,15` |
| Node memory / container limit | 8 GiB / 10 GiB；不設 CPU quota |
| Calibrated I/O budget | 使用 01-53 的 75% raw budget；SHA-256 `12bf0b79c4520ca6d00183ca14b87d321b9221b687cc6e889619876f5b87b2bf` |
| Binary | 沿用 SHA-256 `bf5afef5f75d3bee98c3510e5db386f62d382d5564302b01ff06278a432cdd87` |
| Runner | 沿用已驗證版本，source SHA-256 `e69091188a9fc6890b655d958b0ddecebb5f34d107abd99d4ca305150e058ae2` |

Wallet profile 保持 `wallet-memory-lwt-v1`。每筆已接受 request 只發一個同 partition 的 conditional `INSERT ... IF NOT EXISTS` LWT，測量期間不發 SELECT。Cache 只在 `Applied` acknowledgement 後更新。Unknown commit outcome 必須 freeze 帳戶並 global fail closed。不得自動 retry。Transaction、consistency、timeout、pool、commitlog 或 fsync acknowledgement 行為保持不變。Commitlog batch fsync acknowledgement 不是每個 request 一次獨立 fsync；profile 保持 batch commitlog 與 `O_DSYNC=false`。

## 執行條件與續測門檻

只執行 S=2、C=256。每個 case 前仍執行 strict preflight：可用空間至少為 64 GiB 或估算需求的較大值，CPU busy 不高於 10%，device busy 不高於 5%，available memory 至少 32 GiB，AIO/profile 檢查通過，並取得三筆連續 passing samples。維持原有 source、binary、budget、keyspace、runtime profile、pool、driver counter、完整 verify 和 owned cleanup gates。

C=256 通過 strict validation、Wallet correctness、required metrics、driver counters、runtime profile、owned cleanup 和新增 I/O observer validation 後，由 job supervisor 評估是否執行 C=512。C=512 必須同時滿足以下診斷 continuation rule：

- C=256 RPS 至少為已完成 C=128 S2 baseline 的 1.10 倍。
- C=256 E2E p99 不高於 baseline 的 2 倍。
- C=256 LWT p99 不高於 baseline 的 2 倍。
- I/O observer 與 Prometheus counter validation 均有效。

若 C=256 case 本身失敗，停止，不 retry，也不開始 C=512。若 C=256 完整通過但 continuation rule 未全部滿足，job supervisor 記錄每個 gate 的結果並 skip C=512。不得另跑 smoke、C=128 或 calibration。這些門檻只決定本次診斷是否繼續，不代表統計顯著性、SLA 或正式效能門檻。

比較基線是 [01-53 的 C=128、S=2 case](01-53.development-analysis-scylladb-calibrated-single-node-shard-benchmark.md)：RPS `10076.937000589221`，E2E p99 `369885183 ns`，LWT p99 `29147135 ns`，mean LWT `12.608106 ms`，估算 mean in-flight `127.051`，實測 peak `128`。以該次既有 run 為基線；不重跑或合併其計數。

## 新增 I/O observer

增加唯讀旁路 `benches/scylla_io_observer.py`，以 1 Hz 讀取 host `/proc/diskstats`。它必須確認資料 partition 是 major:minor `8:18`、`/dev/sdb2`，whole device 是 `8:16`、`/dev/sdb`，並用 sysfs 驗證兩者身分和 parent 關係。不得寫入裝置或變更 host 設定。

Observer 分開保留 partition 和 whole-device 原始 diskstats counters，不得把兩者相加。原始值包括 whole-device flush、read/write、in-flight I/O、busy-time 與 weighted-I/O-time counters。分析階段依 counter delta 和實際 elapsed time 計算平均 queue、read/write rate、busy 和 flush await；flush count delta 為 0 時，flush latency 顯示 N/A，不得報成 0。每筆 sample 保留原始值、時間、device identity 和解析狀態。

Runner 保存既有 Scylla Prometheus raw samples；observer analyzer 解析每個 node、shard、`main`/`commitlog` class 與 data mountpoint 的 total ops、delay、exec counters，並計算 counter delta 與 window mean。不得增加 HTTP scrape。Observer 過早退出、缺少必要 metric、counter reset、device identity 錯誤、無法解析，或最大 sample gap 大於 2.5 秒時，將本 case 標成 invalid 並停止後續測試。

Host counters 來自共享裝置。Whole-device flush await 不是單筆 Scylla transaction 的 fsync latency。高 busy 或 throughput plateau 本身不能證明磁碟飽和；結論須一併看 CPU、Scylla I/O queue、commitlog class 和 Wallet latency。

## 驗證、失敗與保存

每個完整 case 必須有 1,024,000 requests 全部 accepted、applied、replied；credit/debit 各 512,000；driver query delta 恰為 accepted；measurement SELECT 為 0；errors、retries、request/connection timeouts 與 unknown outcomes 為 0。必須完整驗證 1,024 個 memory cache accounts 與 1,024,000 筆 ledger rows。CQL pool target 固定 D=6，connection sampler 每筆等於 6；worker/C 和 in-flight peaks 不超過 C。

保留 CPU、Rust CLI、Scylla process、RSS、host diskstats、observer samples、per-stage latency、Scylla shard/class counters、driver counters、來源 hash、strict preflight、correctness、cleanup、continuation decision 和錯誤證據。失敗時先保留證據，再只清理本次可確認 owned 的資源。不得 retry，不得清理 foreign data。

```text
Request
  run_clients -> run_client -> Service::submit
  -> account owner lock + enqueue -> worker_loop -> process_job cache compute
  -> ScyllaStore::commit (one conditional INSERT)
  -> batch fsync -> CL ONE acknowledgement
  -> publish cache on Applied -> worker reply

After all replies
  verify_all -> verify_account / verify_one_account -> owned cleanup
```

```text
Campaign
  strict preflight -> start I/O observer -> fresh owned cluster
  -> runtime AIO/commitlog/I/O profile gate -> preload states
  -> C=256 workload -> verify and clean case -> validate samples
  -> job supervisor evaluates continuation gate -> C=512 or record skip and stop
```

校準後的三個既有階段和本次測試都不是多節點故障域或 production SLA 測試。S2 的 RPS 是單節點總吞吐，不是單 shard 吞吐。維持 P=3 可固定 D=6；增加 worker 數不會增加資料連線數。
