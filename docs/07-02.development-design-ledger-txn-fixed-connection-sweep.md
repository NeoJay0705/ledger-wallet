## Review-driven contract (rev 2; overrides the text above where different)
- **Driver is batch-keyed and self-contained** for selection/termination (small helpers; reuse only low-level helpers from conn_sweep/batch_sweep: idle_gate, extract_row, is_ok(+attempt_dir fallback), tidb_full_window_cpu, flush-rerun predicate, wrapper-run/cleanup logic). Do NOT reuse conn_sweep's effective_primary/saturation/replicate_points/run (keyed by conns, 256 label, continue-on-failure). Subcommands: `run` (resumable; completes selection AND replicates), `audit`, `--dry-run` (writes nothing). No `all/summarize/reclassify/replicate`; a fresh attempt already applies the TiDB reclassification fallback.
- **CSV schema** `artifacts/fixconn-<db>-c<C>[x]-n<N>.csv`: batch, role, attempt_dir, status, exit, go_reached, cleanup, wall_s, duration_s, rps_request, p50_s, p95_s, p99_s, max_s, windows, db_cpu_cores, tidb_cpu_cores, flush_await_ms, client_cpu_cores, imported, cause. Fixed connections N are series metadata (file name).
- **Imports** exactly six finalized effective primaries (batch 50,100 at N=16 for PG c4, PG c8, TiDB c4), taken from connsweep CSVs via conn_sweep's effective row (the corrected † row, e.g. TiDB c4 batch 100 N16 uses the corrected OK row with tidb CPU 3.2388, not the earlier incomplete row), idempotent, role primary, imported=true, attempt_dir/idle paths pointing to the original dir; the † note in `cause` must be preserved (never overwritten by other notes). Old replicates and standard-placement CPU8 rows are NOT imported. Imported points seed the stop logic and are eligible for FRESH replicates.
- **Stop-rule state machine**: points run ascending; the first effective point is the baseline (best = its RPS, streak 0); for each next point finalize any flush rerun FIRST (an OK rerun replaces the primary), then if RPS < 1.05 x best(earlier completed points) streak += 1 else streak = 0; then best = max(best, RPS); stop when streak == 2. Curve completion reasons (distinct, recorded): `stop-rule`, `failure-limit` (non-sampler failure, incl. 30 s timeout, in a primary or its flush rerun), `cap` (batch 8000 completed). Sampler-race retries max 2; if exhausted the curve is incomplete (not a limit) and the campaign stops. Cleanup failure stops everything. Termination must be reconstructible from the CSV on resume (both DBs) and no attempt may be launched after termination. Replicates never influence stopping/saturation.
- **Saturation** = smallest batch with RPS >= 95 % of max over effective successful points of the completed curve (imports included, failures/replicates excluded); results of `failure-limit`/`cap` curves are labelled observed-range. **Replicate set** = saturation point plus its next-lower grid point (only itself if saturation is batch 50), each once, run after the curve terminates.
- **Shared-CPU accounting (CPU8+)**: report client, PD and wrapper/sampler CPU ONCE each from one consistent source (res-pd resource summary; every res-* sampler reads the same wrapper-process ticks, never sum across res-* dirs) and their total as % of the 2 shared logical CPUs; PD capacity 2 / client capacity 2 are individual ceilings, not reserved capacity. Replaces the old client-only bound flag for CPU8+.
- **Report/audit** (fixconn_report.py, tool + fixture tests): tidb % uses the series cpuset size (4 or 6) for normal and † rows, `*` at >= 85 % (3.4 / 5.1 cores); headings/disclosures for 6 vs 4 logical CPUs, SMT, shared sampler perturbation, client limits; audit checks required replicates present, nothing launched beyond termination, completion reason, import provenance, shared-CPU evidence present, corrected † CPU selected, expected windows = 80*ceil(7840/B)+176*ceil(7800/B). The standard-placement reference table is dropped (not required).
- **Resource safety is recorded, not assumed**: keep the 30 s timeout; any failure is a recorded limit; capture client stderr / failure text / OOM evidence in the report. Estimated worst case (linear scaling of batch 100) for standard TiDB c8 N32 batch 8000 is near 30 s, so timeouts are possible and acceptable as recorded limits. Batch 4000 (512 windows) and 8000 (256 windows) are distinct.

## Non-functional
No new concurrency. Large batches make short runs (up to 8000 = 256 windows total); 30 s timeout unchanged; TiDB large literal SQL memory was an issue only with 256 connections x 8000, here 16/32 connections. Expected ~50 runs, 1.5–2 h.
